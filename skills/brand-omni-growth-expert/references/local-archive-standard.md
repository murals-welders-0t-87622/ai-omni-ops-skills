# 品牌业务本地建档标准

目的：每项业务开始前建立或接续能找到的目录，成果按品牌、板块和任务归档；中台仍是品牌业务事实、任务及版本的权威来源，文件目录不代替MCP保存或回读。

## 选根目录与继续原项目

1. 先依据当前品牌上下文、用户指定位置与现有项目确定本品牌工作根目录；如 `客户项目/品牌名/`。不同品牌、同名不同店铺不能混用。不知道品牌根时先查现有项目和中台；无法可靠区分才询问，不随意把成果放进技能仓或其他品牌目录。
2. 在本次任务开始、生成文件之前，按下表创建对应业务路径和当前任务目录。继续已有任务先查其原位置并接续，不因重启、换日期或改版重建另一套；旧目录不自动移动、删除、覆盖或改名。用户指定路径优先，在其位置使用适合的结构。
3. 仅创建当前任务需要的目录；不要为了做一条作品在所有板块建立空文件夹，也不要把用户数据写进公开技能Git。安装技能、单纯查询和没有文件产物的简短问答不制造业务档案。

## 板块路径

以下路径均相对于品牌根目录。板块命名与中台对应；Windows 文件夹不能含 `/`，因此“抖音/视频号”的实际目录名为 **抖音视频号**，不代表平台合并账号或数据。

|---|---|---|
| 全局概览 | `全局概览` | 经营数据、目标与计划、经营复盘 |
| 品牌增长 | `品牌增长` | 品牌资料、产品与服务、市场与竞品、增长报告、战略与计划、复盘 |
| 公域获客·内容规划 | `公域获客/内容获客/内容规划` | 内容战略、策略、选题计划、数据复盘 |

## 每日作品和任务结构

内容作品采用 `渠道/YYYYMMDD/作品名称/`，日期默认是当前本地业务日期，用户明确指定制作日期时采用该日期；发布日期另记，跨日续做保留原目录。示例：

```text
品牌根目录/
└─ 公域获客/内容获客/抖音视频号/20261027/扫把罢工/
   ├─ 素材/      产品图、授权素材及来源引用
   ├─ 选题/      选题、研究与创意依据
   ├─ 文案/      标题、脚本、口播与修改版
   ├─ 制作/      提示词、分镜、剪辑工程或供应商任务回执
   ├─ 成片/      实际完成的视频、封面及审核版本
   └─ 发布与复盘/  发布回执及成熟数据，未发布不造回执
```

同日多条作品各用独立名称；同一作品多平台适配仍关联同一主档及各平台真实版本。商品详情等其他项目采用 `板块/项目/项目名称/`，按本板块表和实际任务建立可辨识的子目录。周期性报告采用 `板块/周期/YYYYMMDD-YYYYMMDD/` 或明确的年月，标注统计口径。战略、策略、执行、结果可以作为具体业务任务子目录，不强加同一模板到所有行业。

文件建议 `主题_用途_V01.ext`，日期、版本及范围要清楚；版本递增、修订保留旧稿和真实成品，不覆盖已确认内容。素材、过程稿、正式交付、执行/发布回执和效果数据分开；没有实际成片/发布/回执就不伪造文件。来源、授权、产品/SKU、任务及中台记录引用写在任务交付说明或现有记录中，不复制密钥、Cookie和无关客户资料。

## 实际创建与验收

可运行 `python <总统筹技能>/scripts/archive_init.py --help`。助手自行根据现有品牌根与业务对象选择参数，用户无需提供技术路径；脚本只创建指定任务需要的目录，要求品牌根已存在，并拒绝越界、非法名称和符号链接。建议先 `--dry-run` 检查，真实创建后核对路径和文件可打开；本地文件是否存在、MCP是否保存成功、实际发布与效果分别检查。已有不符合本标准的文件只记录位置，迁移须先说明范围并按用户指令处理。
