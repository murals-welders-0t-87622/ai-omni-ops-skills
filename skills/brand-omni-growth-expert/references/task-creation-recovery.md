# 创建任务的中断核对（独立 Lab 候选）

仅当实际连接的版本明确提供对应创建入口及操作标识，且用户已经授权创建任务时使用。先确定品牌与已有委托，避免把已有任务再创建一份。独立 Lab 源码有创建与只读核对 MCP 候选；不能假定运行环境已部署，读取当前工具定义及权限，不把查询工具当作创建工具。

在该品牌受保护的本地任务目录准备 `task_creation_operation.py` 的 SQLite 文件，且不要提交 Git。`brandId` 使用已确认的品牌 ID，`localRef` 使用本次创建操作稳定、随机、无业务内容的本地标识；不要写客户姓名、产品标题、凭据或正文。通过 UTF-8 标准输入提供 `request`：它是实际创建请求去掉 `command_id` 和 `idempotency_key` 后的对象，`brand_id` 必须与品牌相同。`prepare` 返回 `commandId` 与 `operationKey`：调用方将其分别填入实际创建请求的 `command_id` 与 `idempotency_key`；业务正文须由原授权资料提供，脚本只记录摘要，不保存正文。该 Lab 版本将 `task_` 开头的 commandId 同时作为任务 ID，可在事件未写入时按品牌核查任务；其他版本不得假设相同规则。

发起请求前，使用相同品牌、localRef 和 operationKey 运行 `mark-attempted`；它只允许一次原子状态转换。同一操作再次打开或并发准备会取回同一组标识；请求内容变动被拒绝。再次尝试标记会失败，此时先查回执，不换新键绕过。准备后崩溃也可能发生在真正发送前，`attempted` 只代表准备发送，不能判断服务器是否收到。

当前连接实际发现 `create_workflow_task` 且具备相应编辑和连接授权时，将完整请求放在 `request` 中调用；该候选仅创建当前品牌内部任务，暂不接受父任务，目标及结束范围均需填写，`source_refs` 需为数组。新授权工作/品牌连接的候选预设包含此工具，旧连接的授权快照不会自动扩权；具体以当前 `tools/list` 和实际调用结果为准。创建回执不等于业务已经执行。

如结果不明，在同一本地记录以 `lookup` 找回标识，再确认当前连接有权限并支持 `inspect_workflow_create_task_receipt`，以 operationKey 在当前品牌查证。`OUTCOME_UNKNOWN`、未找到和无权访问都不是创建失败的证明；保留任务目录与恢复线索，不自动重发、解锁或宣布完成。`RECEIPT_RECORDED` 只证明服务已记录创建回执，仍须核对对应任务及业务进度。旧回执无最小品牌引用时，按工具当前 schema 使用完整原请求，只在其来源和准确内容可恢复时核对。

脚本不连接中台、不验证身份、不保存或验证服务器回执、不完成任务；本地品牌字段只是隔离记录，不是访问控制。守护本地文件权限并保护标识和摘要，避免将可猜业务内容作为 localRef。摘要仅用于本地变更检测，不保证构造出的请求序列化与服务端完全一致；如需重试必须保留完整原请求及其序列化约定，并按当前服务的冲突语义处理。SQLite 在进程重启后的恢复不等于断电、跨机备份或权限安全已验。

此方法仅基于独立 Lab 候选源码与虚构测试，不代表运行中系统、其他版本或 Codex 会自动调用；当发现缺少工具或权限时，继续可完成的工作并明确具体缺口。
