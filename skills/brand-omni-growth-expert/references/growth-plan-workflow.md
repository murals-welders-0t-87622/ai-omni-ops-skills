# 增长计划接力：按需使用

适用于用户要求形成、继续或复盘持续增长计划；仅分析或单项制作不强行建立计划。用户不需要知道内部字段。

1. 首先取得当前品牌和委托范围，发现当前连接的工具与输入 schema。读取已有驾驶舱、已有计划及相关报告；有计划先读取该计划的稳定身份、版本、证据、未完成事项及原外部作业，不按聊天次数重建，不重复发起已受理动作。按数据来源、窗口、店铺、口径和更新时间判断可比性。
2. 没有计划时，基于品牌生意模式、历史数据和用户目标形成可理解的阶段目标、动作与指标；缺数标记未知。用户已经委托创建或保存时，按当前接口填写真实目标、范围、周期和幂等标识；未实际提交不得说已建。创建请求、专业分析、提交结果、生效是不同状态。
3. 在现有接口支持且有权限时提交完整策略及证据，读取服务返回的版本并回读计划和报告；版本冲突先重读，不盲目覆盖。计划生效与报告保存不代表投放、发布、支付或客户触达已获授权或已执行。
4. 到用户要求的检查时机或任务自然触发时，按现有服务能力检查对应窗口；数据不足、未成熟、不可比及真实为零分别呈现。系统检查发现偏差只是线索，不等同专业分析或经营效果；基于实际证据提出建议，由用户选择需要持续跟进的新增实验，按实际能力和授权安排执行。旧计划、检查、决定、回执和新版本可追溯。
5. 外部调用超时，先查原任务/作业状态及幂等键，再决定是否重试；接口缺失、身份或数据不匹配时记录阻塞及可继续部分。不要杜撰工具、专家调用、已运行的定时任务或商业结果。

## 接口发现参考

2026-10-30 在一条本机品牌 MCP 连接的工具目录中观察到 `get_growth_cockpit`、`list_growth_plans`、`get_growth_plan`、`create_growth_plan_request`、`submit_growth_plan`、`update_growth_plan`、`check_growth_plan`、`list_growth_expert_queue`、`claim_growth_plan_check`、`submit_growth_plan_proposal`、`review_growth_plan_proposal` 与 `record_growth_metric_fact`。当时只读调用了驾驶舱与计划列表，写入、版本冲突、重复提交和专家队列均未实测；其他品牌、系统版本和客户端不保证相同。执行前必须实时发现与检查 schema、权限和状态语义，不照抄历史参数。
