# 成果归档与回读

用户要求完成的营销方案、文案、图片、视频和其他成果，应按当前品牌、任务和业务板块保存到现有中台；本地文件和聊天内容不能代替中台记录。用户明确仅要本地成果时尊重其范围。先查任务及已有成果避免重复；采集到的其他人的原作不因这一规则全量入库。

1. 确认当前品牌、业务范围和实际工具及权限，以当前 `tools/list` 和 schema 为准。某品牌连接曾提供 `create_ai_control_center_marketing_plan` / `get_ai_control_center_marketing_plans`（指定 `workspaceScope`、标题和完整 HTML）及 `create_ai_control_center_creative_material` / `get_ai_control_center_creative_materials`；这不是其他品牌或版本均已启用的证明。业务有专属工作区时优先用对应能力，不把所有方案塞入默认板块。文档、素材、作品和采集原片是不同对象；正确选择并关联，避免重复建档。
2. 用户要求使用多元探索的图片能力或指定视频应用时按 [制作能力接力](mcp-production-capabilities.md) 查模型、节点和授权。生成任务成功不自动证明素材已经归档：先查询现有记录，确认产物及存储对象；缺失时使用当前可用的保存接口并关联原任务，不盲目重复创建。
3. 仅记录外部 URL 不等于文件已保存到中台：外链可能失效或无法打开。确需长期留存时按当前接口和权限上传实际文件，读取返回 ID、来源、类型及存储信息；对图片、音视频进一步读取文件并检查可访问、真实格式和解码。分类和标签不能代替文件验证。仅记录外链或拿不到文件时明确标注，不能宣称文件已保存。
4. 保存方案后，使用当前品牌与正确板块回读**同一 ID**，对照完整正文及标题；保存素材后回读同一 ID、品牌、板块、类型和关联。[离线回执核对](../scripts/check_archive_receipt.py)可核对已有回执；它不执行保存、不读取媒体文件，也不验证服务重启后持久性。列表返回受数量限制时查不到只表示本次未核实，不证明写入失败；先用可用的详情或分页能力查证，结果不明不要重复提交。
5. 返回成功和一次读回不证明跨重启持久存储。服务端、数据库、文件存储、访问权限、去重及恢复均需各自验证；未确认时明确告知已保存的证据层级与未验证项。若保存失败或结果不明，保留成果和失败回执、记录恢复点，其他可执行部分继续；不伪造完成或跨品牌写入。

若当前连接实际提供 `get_ai_control_center_marketing_plan_by_id`，可用保存回执的方案 ID 和明确板块回读单条方案；核对品牌、标题、全文后，保留返回的 `sourceRef` 与内容 SHA-256，供需要来源引用的任务记录使用。引用地址要求对应品牌的有效查看权限；方案删除后不可再通过该地址读取，后续核对应比较摘要和可访问性。该引用不是本地文件路径，不要将其伪装成已存文件；有真实文件时仍按实际任务入口登记。此候选只在独立 Lab 隔离环境验证，旧连接或其他版本未必可用；不代表已自动关联或业务执行完成。

若实际连接的方案创建 schema 同时支持 `taskId`、`stageRunId`、`idempotencyKey`，且连接明确授权任务方案关联，已有真实任务与阶段时可带上三者，使保存方案后关联对应阶段。核对创建回执中的 `taskLink`；`failed` 表示方案已保存但关联未完成，不要重建方案，先检查任务、阶段与权限，再使用原操作标识通过 `link_workflow_marketing_plan` 恢复关联。可用 `list_workflow_marketing_plan_links` 核对已关联记录：`changed` 表示方案与关联时摘要不同，`unavailable` 表示当前记录不可读取，不把关联当成果文件、最终完成或发布。查询只返回最近20条。此功能仅独立 Lab 虚构数据与隔离 Codex 工具调用验证；实时 schema 未提供时沿用既有归档，不添加未声明参数，也不假称已自动关联。

对于已合法取得的本地媒体文件，可用 [本地媒体核验](../scripts/check_local_media.py) 检查真实媒体格式、文件摘要并采样解码：通过 UTF-8 标准输入传入 `{"filePath":"本地文件路径","kind":"image|audio|video"}`，其中 kind 必须取其中一个值；已有可信摘要时可附 `expectedSha256`。需安装 ffprobe 和 ffmpeg；文件损坏、类型不符、工具缺失或没有解码样本都不算通过。图片和视频仅检查一帧，音频最多检查一秒；这不证明全文件可播放、内容质量合格、文件来自目标 MCP 或已存入中台，仍须分别核对来源、同一品牌记录与文件读取。脚本不访问网络或上传素材，检测格式有限，无法识别应另行核查，不得判为已通过。

保存本地文件时，以当前客户端的 `tools/list` 为准：若所用 stdio 桥接明确声明当前素材创建工具支持 `localFilePath`，可交由桥接读取并转成 upload；不能同时提供路径和 upload。若只声明 `upload`，按当前工具要求提供文件名、媒体类型与文件内容，不向不支持的远端工具传本机路径。Lab 桥接新适配仅经过虚构数据隔离验证，旧桥接和直接 HTTP 连接不会因此自动支持本地路径；文件大小、内存与实际目标机另行验证。

素材上传后结果不明时，若当前 `get_ai_control_center_creative_materials` 的真实 schema 包含 `includeUploadRecovery`，可在同品牌、同板块带该选项查恢复线索，必要时使用 `recoveryOffset` 分页；分页时新线索可能改变排序，应再次核对。线索也可能是仍在进行的上传，不自动视为失败。`record_present_file_unverified` 仅证明对应记录存在；`record_missing_file_unknown` 表示尚未找到记录且文件状态未知。对照原素材、关联任务与摘要后，按现有权限检查真实文件可访问性和解码；不要自动删除或重发生成。没有此选项或未找到线索不代表文件不存在，旧版或升级前操作尤其如此。

同一份营销方案保存若当前工具 schema 明确支持 `idempotencyKey`，按当前任务及本次保存操作生成稳定、不含敏感数据的标识，并保存在可恢复的任务记录中；超时重试沿用同一标识和原始内容，新建或修订使用新操作标识。同键内容、板块或操作人冲突时先核对原回执，不换键绕过。接口不支持该字段或无法保存标识时，先核查既有成果，不假称自动去重。该能力只在支持它的实际版本和受控路径生效。

### 可恢复的方案保存记录

当前版本支持上述键时，Codex 可在该品牌既有任务目录内使用 [操作记录脚本](../scripts/archive_operation.py)，为每次保存保留跨进程的操作标识。先确认原任务、品牌与本次保存版本；任务或品牌无法确定就先核实，不将名称相似的不同任务合并。新建方案和修订各用自己的操作位置，同一保存的继续或重试沿用原位置。不要把凭据、方案正文、客户资料或操作数据库提交到技能仓库。

脚本从标准输入接收 UTF-8 编码的 JSON；不把正文作为命令行参数或日志。`prepare` 接收 `taskId`、`brandId`、`slot` 和实际保存 `payload`（不含 `idempotencyKey`），在任务目录的本地 SQLite 记录中返回稳定 `operationKey`，随后应向真实 MCP 请求传入该键。脚本仅保存任务/品牌/操作标识和正文摘要，不保存正文；仍需在品牌任务档案或中台保留原始内容。发起调用之前以同一身份和 `operationKey` 执行 `attempted`；查回同一品牌、板块、ID、标题和完整内容后，才传 `recordId` 执行 `acknowledge`。该状态只是本机记录，不能代替真实回执或跨重启存储验证。

对于上述字段齐全的营销方案，可优先用 `acknowledge-verified`：从标准输入传入同一任务身份、`operationKey`、原始 `payload`、`expected`（含 `kind=plan`、`brandId`、`workspaceScope`、`title`、`htmlContent`）以及真实 `createReceipt`、`readReceipt`。它先核对本地已准备的内容摘要，再对照创建和回读中的同一 ID、品牌、板块、标题及全文；未找到、错误或不一致时保留 `attempted`，不确认。旧版本如果因编码差异产生内容摘要冲突，应保留原操作并核查原始内容和回执，不强制确认或换键重发。历史 `acknowledge` 为兼容旧流程保留，只检查调用者提供的 ID，不自行证明回执已核对。核对脚本只检查传入的回执，不调用 MCP、不验证回执真实性或跨重启持久性；材料文件需单独检查实际内容与解码。

方案回读既可以是列表 `items`，也可以是当前连接支持的按键查询 `status=found` 单条结果；`deleted`、`not_found_unknown`、格式错误或内容不符均不能确认。按键查询仍须用原操作标识实际调用；核对器不会自行确认查询请求是否确实使用了该键或来自目标连接。

如果创建回执已丢失，且实际连接已核实使用本项目独立 Lab 的同键方案记录 ID 规则并支持按 `idempotencyKey` 查询，可使用 `acknowledge-recovered-lab`：先用原键在同品牌、同板块调用方案查询；从标准输入传入原任务身份、`operationKey`、原始 `payload` 和真实查询 `readReceipt`。脚本核对查询状态为 found、记录 ID 符合该 Lab 版本的品牌与操作键规则、品牌/板块/标题/全文与原内容一致，且本机操作记录已标记 attempted，才确认；不需要补造创建回执。deleted、未知、内容不符或版本规则不明均保持未确认。此方式只核对调用者提供的回执，不能验证回执来源、真实权限或磁盘持久性；其他中台版本不得假设其 ID 规则相同。候选仅在虚构品牌和隔离真实 Codex 工具调用中验证，尚未部署到现有中台，也不证明对话能自动调用或恢复。

同一操作位置内容改变时脚本拒绝复用；另一次明确的新建或修订才换操作位置。恢复时若返回 `attempted`，表示结果可能未知，先用该键查已保存、已删除或未知状态；未知不等于失败，也不能自动重新生成、换键或断言未保存。若返回 `acknowledged`，先回读对应记录，不再次保存。多端同步、本地磁盘丢失、手工删库、不同客户端或无法确定同一任务时，这个本地记录不保证去重；当前脚本不自动调用 MCP，也不自动判断业务完成。
