# 品牌增长报告：分析、分工与交接

## 在什么情况下使用

用户需要完整品牌增长报告或重做品牌级策略时使用本流程；已批准方案的执行、单平台任务和持续增长计划按任务终点接续，不为套模板重新跑整份报告。先读当前品牌资料、产品、经营事实和已有报告，再选择相关领域技能和资料；未发现的材料明确记为缺口。资料的历史品牌专用规则不自动变成其他品牌的规则。

## 八类输入与判断

检查品牌基础、经营现状、产品交易、用户市场、公域、私域、资源约束、增长目标：标出来源、时间、适用品牌、已知事实、冲突和缺失。信息足够时完成完整分析；部分不足仍交可用方案，将受影响的结论与测算标记待验证；客户、产品或主要生意模式等关键对象无法判断时，先提出最少业务问题，不索要技术参数。不能把渠道、经营指标或增长成效补造出来。

## 经营推演与专业分工

1. 先说明谁有需求、有什么痛点、品牌靠什么产品和服务解决、替代方案是什么、差异化有什么证据，以及目前哪些渠道带来客户和收入。对照老板与各角色是否围绕同一增长方向工作，指出最主要的协同断点。
2. 按当前真实数据及业务模式拆解财务结果与驱动因素。以电商为例，同一范围和周期内，支付金额可按支付订单数×每单支付金额，或按去重支付买家数×每位买家支付金额推演；访客×访客支付转化率可估算买家数，须保持访客/买家的统计口径一致。复购体现为指定成熟队列的再次购买，既可能影响买家数，也可能影响购买次数和人均金额；不得无定义地把复购率再乘入已包含老客的支付金额。其他行业采用与其成交和交付方式匹配的指标模型。
3. 各相关领域以实际技能完成分析：公域与 GEO 共用客群痛点、可信证据和内容资产，但各自验证渠道表现；电商承接商品交易；私域与销售分别设计客户生命周期、服务和成交接力；营收分析核对渠道贡献、预算、毛利和 ROI 口径。只有实际调用其他执行体才记录其参与，未调用则说明由当前 Codex 综合对应专业方法完成。
4. 根据实际业务周期制定分阶段目标、优先动作、资源和责任人，以及复盘指标；可使用季度路线，但不能强制所有任务采用一年周期。各动作说明预期改善什么指标、为什么有效、依据和依赖，保留假设和实际结果区别。
5. 完整报告依次覆盖品牌诊断、机会洞察、营收增长、营销策略、增长结论与优先级。每章至少回答结论、事实依据、问题机会和下一步，首屏优先展示老板需要决策的阶段重点、目标和动作。跨内容、搜索、电商、私域、销售与服务写清谁承接谁、客户反馈如何回流。

## 归档和下游接力

发现当前品牌可用的 MCP 工具及 schema，先完成报告正文，再按当前能力保存到品牌增长报告；回读品牌、正文、版本和状态。记录可供下游引用的报告或方案标识以及适用周期，后续内容、渠道、销售及复盘主动读取适用版本；没有可用写入或回读能力就交付本地可查看成果并标明待归档，不能声称已保存或已被其他模块使用。计划保存、负责人确认、外部执行与经营效果分别核验。
