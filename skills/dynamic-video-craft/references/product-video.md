# 产品片路线

## 从功能到镜头

先确认用户希望观众记住什么，再选运动手法。典型结构为提出问题或核心承诺 → 功能因果演示 → 结果或证据 → 品牌与下一步。镜头数量与时长随内容调整，不套固定六镜公式。

| 要表达的关系 | 可选视觉动作 | Shotcraft 卡检索词 |
|---|---|---|
| 多个来源汇聚 | 数据沿路径进入共同节点 | bezier-source-converge-merge |
| 一批内容进入工作台 | 卡片发出、加速、归位 | deck-deal-flyin |
| 操作触发可见结果 | 输入、筛选、列表收敛 | type-and-filter |
| AI 完成一项任务 | 结论先出现、证据补齐、完成态 | ai-stream-response |
| 状态或版本对比 | 同一位置用分割杆揭示变化 | before-after-slider-scrub |
| 页面细节值得看 | 从整体推向细节，其他区域降权 | spotlight-hero-card / cursor-flyover |
| 品牌收束 | 把功能主体的形状交接给品牌 | ui-to-brand-morph / logo-shrink-wordmark-lockup |

这张表只用于定位，不代表这些卡已经复制进模板。卡片的准确变体与源文件通过 `recipe_catalog.py` 和对应文档确认。

## 素材采集

对真实产品，取得公开页面、用户给定的可用页面或本地开发页面；页面需要登录时用当前环境允许的浏览器工具。不要把“做视频”理解为可修改业务数据。截图前等待字体和图片加载、动画稳定；避免把光标、悬停菜单或加载骨架意外截入。

按镜头需要采集全页图、必要元素切片与空背景；记录图片尺寸、浏览器视口、DPR、滚动位置以及关键元素边框。所有标注采用同一个页面坐标系：

```text
图像坐标 = CSS 页面坐标 × DPR
屏内点 = 图片显示起点 + 图像坐标 × 显示宽度 / 图片原始宽度
```

若图片还有裁切、内边距或相机变换，要将这些变换一并计入；优先把标注与图像放进共同父层，减少二次计算。画面里无法读清的小字用独立高清切片或合规的文字标注补充。

## 视觉与节奏

沿用目标产品的视觉 token，参考片主要提供运动和剪辑语法。飞入的元素要落入有意义的位置；比较应保持共同基准；数据增长先标清单位与来源。相同特效可以作为风格重复，但不要让连续几个功能都变成相同卡片依次淡入。

有指定强节奏音乐时，从真实音频分析时间点，记录 BPM、起拍相位与重要瞬态。规则拍可计算 `phase + beatIndex * 60 / BPM`；变速或弱鼓点音乐使用实际事件表，不强行拟合固定 BPM。大转场用强拍，阅读停留不被每一拍打断。

声音从动作的起因和触感选择：准备段可用上升音、移动用掠过声、落点用短冲击。以样本内部的实际冲击点对齐画面落点，而非把文件起点一律贴到动作帧。连续卡片可用一组声音概括，避免每张都打一下。

## 指定 Ink Press 时

先读上游固定版本的 `template/TEMPLATE.md` 与 `template/package.json`，再在独立目录取得模板。依次替换原品牌、字幕、截图、坐标、镜头表及声音；逐镜验证。它的既有示例内容与用户的产品并不等价，不能只换片尾 Logo。
