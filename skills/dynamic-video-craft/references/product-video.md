# 产品片路线

## 从功能到镜头

先确认用户希望观众记住什么，再选运动手法。典型结构为提出问题或核心承诺 → 功能因果演示 → 结果或证据 → 品牌与下一步。镜头数量与时长随内容调整，不套固定六镜公式。

| 要表达的关系 | 可选视觉动作 | Shotcraft 卡检索词 |
|---|---|---|
| 多个来源汇聚 | 数据沿路径进入共同节点 | bezier-source-converge-merge |
| 一批内容进入工作台 | 卡片发出、加速、归位 | deck-deal-flyin |
| 操作触发可见结果 | 输入、筛选、列表收敛 | type-and-filter |
| AI 完成一项任务 | 结论先出现、证据补齐、完成态 | ai-stream-response |
| 状态或版本对比 | 同一位置用分割杆揭示变化 | before-after-slider-scrub |
| 页面细节值得看 | 从整体推向细节，其他区域降权 | spotlight-hero-card / cursor-flyover |
| 品牌收束 | 把功能主体的形状交接给品牌 | ui-to-brand-morph / logo-shrink-wordmark-lockup |

这张表只用于定位，不代表这些卡已经复制进模板。卡片的准确变体与源文件通过 `recipe_catalog.py` 和对应文档确认。

## 素材采集

对真实产品，取得公开页面、用户给定的可用页面或本地开发页面；页面需要登录时用当前环境允许的浏览器工具。不要把“做视频”理解为可修改业务数据。截图前等待字体和图片加载、动画稳定；避免把光标、悬停菜单或加载骨架意外截入。

按镜头需要采集全页图、必要元素切片与空背景；记录图片尺寸、浏览器视口、DPR、滚动位置以及关键元素边框。所有标注采用同一个页面坐标系：

```text
图像坐标 = CSS 页面坐标 × DPR
屏内点 = 图片显示起点 + 图像坐标 × 显示宽度 / 图片原始宽度
```

若图片还有裁切、内边距或相机变换，要将这些变换一并计入；优先把标注与图像放进共同父层，减少二次计算。画面里无法读清的小字用独立高清切片或合规的文字标注补充。

从显示位置反推素材位置时，不要默认横纵方向缩放相同；非等比缩放、旋转、裁切和多层变换需使用完整变换关系或逐项换算，验证起点、中途和终点是否仍指向同一对象。画中画复制视频时，框内外要共用同一时间基准并检查对应帧；周期性纠偏或固定秒数容差只能提示误差，不能证明逐帧同步，必要时改用同一帧源或在渲染时按时间戳对齐。示例截图和人物占位不能冒充真实素材或经营证据。

## 功能演示与重点引导

讲真实产品操作时，先明确观众要理解的操作、实际界面的起始状态与结果。录屏或真实截图可用可见光标引导：到目标后短暂停留，点击与对应的界面响应同步；拖拽时光标与被拖对象保持同一运动。镜头配合旁白，不为了动画密度遮挡按钮或结果。用截图重建的演示要标明为示意，不能把动画响应当成已实际操作或产品具备未验证的功能。

多步软件演示可建立一份事件表，包含步骤、语音锚点、目标控件、动作和可见结果，由同一时间点驱动光标与控件状态；坐标随界面布局测量，拖动时手柄、读数和光标使用同一进度。录屏或重演必须核对真实功能、前后状态及可展示权限。进度条、清单和成功提示只有在真实回执支持时才代表实际进度或完成；示例值与模拟过程应明确标为示意，不能靠动画制造成功。

多次进度变化若在前一动画尚未完成时到达，要从当时实际显示值衔接或按设计重新安排时间，检查百分比与进度条同步；状态、勾选和完成态仍以对应事件为依据。不要把旧事件目标值当成新事件开始时已显示的值，否则可能突然跳动。

片尾可依据品牌视觉将标识、名称与辅助文字错峰呈现，并留足识别时间；替换示例中的占位标识、文案和画幅，核对品牌名称、清晰度与使用授权。引导关注时按发布平台实际操作设计画面，让移动、按下、状态反馈有可读的先后关系，避开字幕和界面遮挡；这只是视频中的示意，不能宣称观众已经关注，也不把某种动效或出现次数保证为增长效果。

展示账号资料时，姓名、账号、认证标识、粉丝量和引用帖文只使用可核实且有权使用的信息；动画中的模拟点击不是真实关注或增长。数字动画不得通过放大变化伪造社会证明；显示为万、千等缩写时还须核对实际数值与取整规则，不把显示跳变当作一次真实新增。无法确认的数据省略或明确标为示意。

讲解代码、配置或操作日志时，选择有授权的实际材料并去掉凭据与敏感信息；无法展示真实记录时标注模拟，不能以拟真的终端证明真实运行。较短代码可按讲述聚焦当前行，镜头和高亮共用行位置，保留上下文与空格，最后回到全貌；长行和中文按实际字体测量，检查裁切及可读性。命令与结果须分别核验，代码画面或绿色成功提示不代替执行回执。

把真实过程重现为动画时，按实际调用标识关联开始、结果和失败状态；状态图标依据对应回执变化，不以“下一行出现”代替该调用完成。省略日志要保留影响判断的失败、重试和上下文，不能把多次操作拼成一次成功。文字逐步出现时以可见字素为单位，检查表情及组合字符不会被截断；对话和日志容器按实际内容调整，避免固定高度掩盖结论。

需要解释复杂界面时，可依次标注目标、连接线与短标签，标签放在空白处；或者适度压暗周边，按讲述顺序切换焦点，保留足够上下文并在结束后恢复。仅在确有必要时放大细节：镜内应来自同一份真实截图并与原位置对齐，标明出处，避免遮盖源内容。多个资料图可以错峰展示，但应保证原文、关键数字和来源可读；资料呈现的视觉冲击不等于证据充分。

需要跟随移动的界面目标时，相机位置从该目标的实际坐标计算，随内容变化同步更新；检查裁切边界并在需要时拉回全貌。长命令按实际字体测量，别假设所有字符宽度相同；真实录屏与重建动画分开说明，绝不展示真实密钥或客户隐私。

## 视觉与节奏

沿用目标产品的视觉 token，参考片主要提供运动和剪辑语法。飞入的元素要落入有意义的位置；比较应保持共同基准；数据增长先标清单位与来源。相同特效可以作为风格重复，但不要让连续几个功能都变成相同卡片依次淡入。

页面演示可先围绕表达目的选运动：推近适合从全局聚焦一处，拉远适合从细节交代整体背景；超宽流程可沿实际阅读方向横移，长页面可依讲述依次停靠关键区域。逐项记录实际截图尺寸、兴趣点、运动起止与旁白时间；每处留足阅读时间，不强制不停运动。需要给页面空间感时可适度倾斜，但要检查远端文字、四角和遮挡，必要时保留正视画面或另做高清局部。

长镜头以空间表达流程关系时，先画站点与相机路线，标出世界内容和固定屏幕字幕，检查从一个站到下一站的整个可视范围。连续展示不能提前露出尚未到时的结论，路途中不要无意展示半成品或无意义空白。镜头可以折返服务叙事，但先解释方向并保持空间关系清楚；长页巡览通常按内容顺序，需回看时应让观众理解原因。

长页滚动按实际内容高度和视口确定最大滚动距离及停留点；页面比视口短、目标靠近首尾或加减速距离不足时，缩短或跳过相应段落，避免滚出页面或反向跳动。用所选缓动的实际导数核接点速度，保留足够阅读时间；换素材、画幅或字体后重新测量。

放大截图前按实际源分辨率、裁切、最大缩放和输出尺寸核清晰度，静帧与运动段都要抽看。相机的缩放和位移应以统一时间与实际变换顺序计算；基于兴趣点的缩放要复核点是否仍指向目标、画幅边缘是否露出非预期背景。运动段连接时按所用缓动曲线计算起止速度与位置，静止停留可用于阅读，不以持续漂移或固定像素速度作为通过条件。

适配推拉或视差镜头时，验证每段实际缓动曲线及位移对应的接点位置和速度，不把“平均速度的一半”当成任意曲线都成立；按叙事需要选择连续运动或有意停顿，并抽帧、播放检查。起止缩放相同或运动距离为零时明确采用静止分支，避免计算比例时除以零。光标跟随应在字体加载后根据实际排版、字形和视口边界测量位置，混合中英文、合字及长文本要重新核对，触及边界时允许不居中。

有指定强节奏音乐时，从真实音频分析时间点，记录 BPM、起拍相位与重要瞬态。规则拍可计算 `phase + beatIndex * 60 / BPM`；变速或弱鼓点音乐使用实际事件表，不强行拟合固定 BPM。大转场用强拍，阅读停留不被每一拍打断。

声音从动作的起因和触感选择：准备段可用上升音、移动用掠过声、落点用短冲击。以样本内部的实际冲击点对齐画面落点，而非把文件起点一律贴到动作帧。连续卡片可用一组声音概括，避免每张都打一下。

## 指定 Ink Press 时

先读上游固定版本的 `template/TEMPLATE.md` 与 `template/package.json`，再在独立目录取得模板。依次替换原品牌、字幕、截图、坐标、镜头表及声音；逐镜验证。它的既有示例内容与用户的产品并不等价，不能只换片尾 Logo。
