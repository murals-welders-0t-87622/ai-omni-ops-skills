# 旁白解说路线

## 先把可听见的时间确定下来

已有录音：测量真实时长并转写/对齐到用户稿件。只有文字：先完成适合朗读的稿件；如当前环境具备可用 TTS 且用户的制片请求包含配音，使用已配置的能力。没有可用合成或录音时先做静音预演，并只向用户索取必要的配音输入。

分别保存朗读稿和显示稿。数字、单位、英文缩写的实际读法用于对齐，显示稿可以保留 `24%`、产品型号和标点。不要为了适配某个对齐器把用户的所有字幕数字一律改成汉字。

可接受带词级时间的 ASR、强制对齐或用户已有精确时间戳。ASR 的结果是估计，关键重音要回听；中英混读、人名、同音词、停顿是优先检查点。SRT 句级时间不能冒充字级时间。

归一化到本技能的 `anchors`：

```json
{"id":"s02-key1","text":"自动归类","start":6.12,"end":6.71,"source":"audio-alignment"}
```

`events[].anchorId` 引用该 ID，`at` 从锚点读取。模板只消费已确定的时间戳，不捆绑模型、不假装能自动完成语音识别。时间轴检查能验证数据之间的偏差，不能证明这些时间真的与录音一致。

## 按语义组织画面

一段论证可以跨多句保持同一场景。先确定主任务：定义、举例、比较、数据、流程、转折、结论；再决定每个重音让现有对象发生什么变化。新增对象之前决定上一对象是否还需要存在。

| 讲述内容 | 适合的视觉响应 | Talkcraft 参考卡 |
|---|---|---|
| 一个数字或变化 | 数字演算、终值与单位一起落定 | number-counter / metric-with-sparkline |
| 一步步过程 | 线条生长、节点接力、相机跟随 | step-timeline-vertical / ui-flow-theater |
| 来源与证据 | 实际页面巡览、放大、划重点 | evidence-scroll-tour / highlighter-sweep |
| 纠正常见误区 | 划掉旧结论并替换 | strike-and-replace |
| 多个有关联的概念 | 二维空间站点与连续相机路径 | long-take-world / stage-keyframe-tour |
| 段落转折 | 沿运动方向进入下一主体 | push-through-transition / whip-pan-transition |

这些是链接式参考；使用上游实现前查看来源说明中的许可。也可以用标准 Remotion API 独立实现相应关系。

每镜的导演记录至少说明：背景是什么、主体是谁、相机去哪里、说到哪个词发生什么、下一主体出现时旧信息怎样退出。资料图中的标注跟随内容运动，字幕固定在屏幕空间。人物出镜时保护人脸与手势表达，不默认要求所有视频都含人物或头像。

## 避免时间上的误导

- 强调数字、反转答案等由词触发的内容，在锚点之前真正不可见；不能靠调低透明度提前泄露。准备画面可以先出现，关键结果到词才揭示。
- 镜头开始到首个重音之间安排承载内容，如前一镜延续、实拍或正在运行的流程，不让空背景等配音。
- 重音离镜尾太近时，延长镜头或改编排，给结果留下阅读时间。脚本对最后 0.5 秒内的事件报警；具体停留仍按内容密度判断。
- 转场遮挡峰值和 SFX 落点也进事件表；改变旁白或镜头长度之后重新计算，不能只挪画面。
- 长镜头按二维站点规划，预览相机途中会看到什么，避免把空白路程和半成品内容带入画面。

## 字幕与混音

字幕以阅读为先，按语义拆行；字幕和画面花字承担不同角色。竖屏给平台底部说明与右侧操作栏留出空间，实际发布平台的 UI 可用截图核对。旁白保持前景，音乐与音效避开主要字音；不要仅凭固定音量数字宣称听感合格。

字幕文件由最终时间轴导出；最后一句、尾音与片尾停留一起核对。精度描述区分对齐误差和帧量化误差：30 fps 最近帧量化最多约 16.7 ms，但原始 ASR 可能误差更大。
