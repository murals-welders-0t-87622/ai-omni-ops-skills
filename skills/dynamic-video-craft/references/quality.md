# 验收方法

验收围绕观众实际看见和听见的内容。先解决事实、缺素材、裁字、重叠、时序和音画错误，再处理质感；不为满足抽象指标而给静止图表硬加抖动。

处理透明头像、Logo或贴图时，先保留原文件；按画幅要求明确选择等比缩放、留白或裁切，检查输出尺寸、透明通道、背景合成、文件格式与体积。不要默认把非正方形素材直接拉伸成正方形，或在转 RGB、JPEG 时丢失透明度；确需不透明背景时指定背景并查看实际效果。输出文件扩展名、引用路径和编码格式须一致。

同名或同长度的不同编码人物视频不一定是同一画面版本：换用另一格式前分别核对时间戳、开头及代表性对应帧的人物动作、口型和透明合成；若不同步，使用已核对的素材版本并调整时间映射。单帧相似、容器时长相等或解码成功都不能证明整段完全一致。

透明数字人视频先在实际目标浏览器、剪辑器或渲染器中叠到浅色与深色背景，检查人物边缘、透明区域和目标时间段；视频能播放不等于透明层已保留。WebM/VP9 的透明信息可能依赖具体解码器：若默认 ffprobe 显示无 alpha 而文件标记含 alpha，使用支持 alpha 的解码路径再提取检查（例如本机支持时显式指定 `-c:v libvpx-vp9`）；仍以目标播放器实际合成为准。容器扩展名、用户代理或格式支持说明都不能单独保证兼容。检查伴随音频是否存在，口型对应的真实音轨和同步须另验；素材授权与人物肖像授权也分别核实。

展示 AI 对话或编码过程时，优先采用经授权的真实录屏、核实过的对话或执行回执；若按这些材料重建或使用模拟内容，要明确标注“演示”或“重现”，不把拟真界面、状态点或编排出的日志作为真实操作证据。展示前检查敏感信息；长提示词和日志按画幅调整版式与时长，避免裁切改变意思。产品外观和标识使用需分别核查来源、许可及当前版本。

## 渲染前

运行 `check_timeline.py`、TypeScript 编译，确认素材存在、时间范围正确、镜头连续、事件属于正确镜头、引用的锚点存在。核对真实旁白时长。检查脚本不会识别实际画面的布局、真实 ASR 精度或声音质量；这些不能仅凭 PASS 放行。

文档自查如只搜索固定文字、数量或设计令牌，结果只能说明配置文本出现过，不能证明镜头按要求生成、素材可读或商业事实正确。样本画面测量须核实际分辨率与时间、抽帧成功及样本范围；固定坐标、背景颜色或一秒一次采样可能误判和漏掉短镜。布局令牌算术检查还不能覆盖阴影、实际字体、嵌套样式及渲染遮挡，需结合目标画幅播放检查。

每类自动验收先建立预期镜头和目标对象清单，再记录实际检查数、缺失数、跳过数及原因。预期存在的页面、图表或文字没有被检查时为未验证，零检查、选择器未命中或缺少文件不能因失败数为零判通过；确认确实没有此类对象则标记不适用。检查结果要关联具体版本和时间点，抽样不能写成全量覆盖。

接入外部验收脚本时，先用已知错误的隔离样例验证其失败是否确实阻断：有的脚本会在日志写出失败数量，进程仍返回成功。应同时核对退出码和实际结果中的检查数、失败数、跳过数；结果缺失或无法解析记为未验证。不要在已有脚本上只看退出码就宣布通过，也不覆盖真实业务文件来制造失败样例。

参考视频的固定尺寸、分栏间距、字幕样式和检测阈值属于特定项目；对照设计文档、实际样式和预览，如版本不一致以当前目标和渲染结果为准。代表镜头能及早发现共性问题，但不能证明未抽查镜头全部合格；静态占位人物也不证明真人或数字人口型和音轨完成。

## 关键帧与运动段

每镜看信息落定的一帧，复杂镜头额外看入场中段。对转场、数字替换、人物换位看边界前后的小段视频；单帧无法证明没有抖动或闪烁。需要精确卡片复刻时将参考动态片段与本片并看，比较路径、停留、节奏、遮罩、方向和收尾，不只比较最终截图。

对“点击时光标落在目标上”“答案与口播同时揭示”等瞬间约束，单独检查目标帧及前后帧，并播放片段核对连续运动；常规随机抽帧未命中不能算验证。数字人或抠像镜头同时检查人物完整性、关键动作和字幕/卡片避让；特意裁切的镜头按其叙事意图判断。

人脸检测结果只覆盖实际检出的采样帧和被选中的人脸，不代表全部帧或所有人物均已检测。低检出率、遮挡、侧脸、人物切换和变帧率都需追加核查；把素材坐标按实际裁切、缩放和运动变换到画面坐标，再检查文字及其背景的交叠。未检测或漏检部分记录为未知，不能只凭检测框声称全片安全；模型下载和素材处理应符合当前环境与授权。

肤色像素质心只能提供候选位置，肤色相近的背景、手部、不同肤色及光照可能干扰，不能等同已检测到人脸或精确人物中心；结合人脸/人物定位与实际画面复查。预览几何应在需要的多个时间点分别测量，截图拍了多个时点不代表几何也在每个时点检查；将预览坐标换算到成片坐标时核对实际缩放、裁切与设备像素比。

帧间差分同样只反映画面变化：运动背景、镜头移动、灯光变化或编码噪声可能进入掩码，静止的人物也可能漏掉；先检查帧间对齐和分辨率，查看掩码，并结合人物检测或画面确认，不把“运动区域中心”当作人物中心。`object-fit: cover` 裁切需按各布局的实际尺寸、人物位置反算；如果可裁切范围不足以让目标居中，应保留可达性限制并调整构图，不把钳制后的边界值说成已居中。

预览脚本若依赖实时定时器、循环播放或帧数到毫秒的固定换算，与逐帧渲染的任意时间跳转可能不同；对同一镜头核对预览和实际输出的目标帧、重复播放复位及时间基准，静态预览通过不代替最终视频播放验收。

横竖屏分别核字号、边距和截图裁切，不能只改变 Composition 尺寸。核对姓名、单位、数值、来源行；避免一屏多个巨型数字争夺注意力。图片上的标注必须在移动后仍准确。

数字人和信息图同屏时，低对比或文字消失先区分：被人物或其他层遮挡、文字溢出画框、颜色对比不足；结合实际图层、边界与画面检查，不能一律加描边或底色。对背景视频造成的可读性变化，可在相同时间点比较有视频和无视频两版，分别记录原有问题及新增问题。

画面内容疑似缺失或被遮挡时，可在同一时刻、同一画幅与坐标下，对照含人物和不含人物的画面层，并结合实际 DOM 边界、裁切与播放检查。编码损耗、透明度、背景动画和采样偏移都会影响像素差；非白像素占比、亮度阈值和零差异都只能辅助判断，不能单凭它们认定人物或文字不存在。竖排文字还要检查容器高度、换列方向及祖先裁剪，避免为了通过占比指标加入无关装饰。

诊断遮挡时记录缺失的镜头和未命中的文字；缺文件即使脚本最后输出“无挡住”也不能认定通过。元素矩形相交只表示可能重叠，实际遮挡还取决于层级、透明度、裁剪及运动；元素中心的图层栈只能反映一个位置，文字边缘、其他采样时刻和小字仍须核查。预览与最终画面应定位同一内容和对应状态；动画进度百分比相同不一定是同一绝对时刻，生成并排截图也不等于已经人工看过。

由画面反推字幕位置和字号时，先确认源视频解码、分辨率和采样帧，保留未检出样本数。固定颜色、描边、画面区域和字幕居中的假设可能漏掉其他设计；像素块高度只是估计，不等于准确字体字号。画幅或裁切发生变化时重新测量，而不是一律按示例比例换算。

图表变形时核对实际显示框与 SVG 的 viewBox 比例及缩放方式；不等比拉伸需同时检查横向和纵向变化。图表高度不足时还要检查父容器分配、同屏组件争用和内边距，而非仅修改 SVG 属性。检测脚本只选需要保持图形比例的图表，装饰性细线与有意拉伸的元素按设计分别判断；不同尺寸、布局和动画时刻都要结合真实画面验证，不能套用旧项目阈值或单凭探针断定视觉合格。

探针统计 DOM 节点、动画或样式数量只能提示与设计稿的差异，不能以数量证明画面有信息或表达有效，也不能为了达标堆装饰。需要读的文字包括实际字幕、小字号和 SVG 文本，确认哪些被选择器排除；截图灰度差或区域最大最小差不是 WCAG 对比度比值，不能据此声称符合无障碍标准。对半透明遮罩前后对比，先固定同一视频帧、画幅和其他图层；视频不同步、渐变遮罩及叠层会影响统计，结果只作线索，仍看实际成片。

涉及真实数据的动画，图形、数值、比例和轴刻度须共同反映同一状态；检查入场中间帧及最终帧，不让过冲、独立缓动或装饰性曲线暗示超出证据的变化。范围、时间和单位须可辨；未知数据保持未知，不为丰富看板补造数值。

抽查数值首次可读及落定的帧，确认小数、单位和对应类别完整；检查图表基线、刻度与增长计算。路线核对地点和方向，并区分真实轨迹与示意。标注逐帧核目标与来源上下文；放大画面同时检查源素材版本、对应帧、裁切及同步情况。以上检查需实际预览，不以配置或同源文件代替证据。

同一画面或口播同时出现总量和日均、增长率等派生数时，按实际统计起止日期、单位与舍入规则独立复算并交叉核对；不沿用模板示例值。编号或带前导零的代码按字符串处理，不能先转成数值丢失位数；数字滚轮也要检查负号、小数、分隔符、较大数值和最终落点。若数字、小数或单位分批入场，检查中间帧不会让观众将不完整数字误读成完整结论。

产品操作演示抽看按下前、按下与结果出现的连续帧和播放片段，检查光标落点、状态变化及拖拽同步；聚焦、连线和放大区域应始终指向同一份截图的正确位置。检查标注及放大镜不遮住关键原文、字幕或来源；不同画幅核重新定位后的可读性。截图经裁剪、缩放或更新后重新核坐标，不仅检查首帧。若为示意动画，核对示意标识与实际能力描述，视觉演示不构成真实操作回执。

## 成片检查

```text
ffprobe -v error -show_entries format=duration:stream=codec_name,width,height,r_frame_rate -of json out/video.mp4
ffmpeg -i out/video.mp4 -vf "blackdetect=d=0.25:pix_th=0.10,freezedetect=n=-50dB:d=1" -an -f null -
ffmpeg -i out/video.mp4 -af volumedetect -vn -f null -
```

运行检测时先确认输入文件可解码、命令退出码正常，再读取检测结论；脚本只要未匹配错误日志就报通过的结果不可靠。按视频真实帧率或实际时间基准抽查目标时刻前后帧，不能固定按 30 fps 推算所有素材；变帧率素材尤其要核实际时间戳。抽帧、浏览器跳转预览和线性播放可能表现不同，转场、资源加载与动画还需核对实际渲染和连续播放。

音效检测先确认文件编码、采样格式及声道；多声道相位相反时简单平均可能抵消信号。底噪差值和峰值只是候选线索，静音基线、极短音效与混音掩蔽需单独检查，最终仍听成片中音效与旁白。布局探针的跳过项或警告应记录为未检查，不能等同通过。

黑场与静止检测只是候选提示：设计过的黑底、Logo 停留、细微动效都可能被标记，应对照镜头表判断。还要确认首尾帧、总帧数、最后一句和音轨没有截断；音量统计不能证明语音清晰或音效可听。

至少实际播放代表性镜头和转场；在有音频播放能力时听开头、重音和结尾，检查配音误读、音乐掩蔽、音效落点与尾音。当前工具无法听音时如实记录该限制。

修改后只重验受影响的镜头及其接缝；全片时间或音轨变动时复查全片时序。交付只描述实际完成的验证，不沿用上游测试报告的结果。

根据用户指出的具体问题返修时，记录问题描述、原片位置、修改范围和实际采取的措施；比较修改前画面、修改后对应画面和最终输出中的结果。若剪辑导致时码变化，先映射到相同内容再比较，不机械对照同一秒数。涉及缩位、揭示或遮挡的状态变化，检查整个受影响区间及边界，而不只看一张批注截图；复发时记录前次修复未覆盖的原因。需要声音或运动才能判断的问题，仍要播放或试听对应片段。
