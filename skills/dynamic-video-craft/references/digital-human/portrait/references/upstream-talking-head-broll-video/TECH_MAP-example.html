1 · 测量层：先量，再设计

"像素级模仿"的前提是先有像素级数据。这一层不产出画面，只产出数字。

技术用在哪产出
Python + NumPy 把参考视频每帧解成 H×W×3 数组，做行/列亮度剖面扫描 边框宽度、白边像素、黑描边位置
FFmpeg rawvideo 管道 -f rawvideo -pix_fmt rgb24 - 抽单帧直入内存，不落盘 460+ 帧采样，无中间文件
连通块 + 双条件掩码 字幕检测：白>232 且 描边<105，取最下连续块 字幕 26px（p10=p90，151 帧）
列投影布局聚类 与背景差分 → 列掩码 → 连续块宽占比分类 FULL/SPLIT/WIDE 71 段布局，SPLIT 50% / FULL 45%
为什么必须自己写扫描而不是目测？
前一版靠目测把字幕做到 138px，实测应为 39px，超标 3.54 倍。 两套画框差异（左框 9px 白边 vs 右框 3px 黑边）目测同样看不出来 —— 只有逐像素打印数值才能发现。 
# 关键手法：一维亮度剖面，1px 精度定位边框
row = img[y].mean(axis=1)          # RGB 均值 → 灰度行
# 实测输出：190 189 191 ... 203 | 77  4 | 163 238 | 229 ...
#           ↑背景+阴影          ↑2px黑描边  ↑过渡   ↑卡片内容
# 值 4 ≈ 纯黑 → 判定 B-roll 框为 2px 黑边，且无白色内边框

1b · 几何测量层：中缝 26px 的取证 （本项曾出错）

用户指出 A-roll 与 B-roll 叠在一起。第一版靠"31.1% + 64% + left:0 + right:0"分栏， 实测 DOM 间距为 −9px（真实重叠）。这一层专门把 SPLIT 的四条边全部量成绝对像素。

技术用在哪产出
横向剖面双边界定位 同一行同时找 A 框白边右缘（>=240）与 B 框黑线左缘（<=40），差值即中缝 中缝 26px（原生）
限定扫描窗抗污染 r[380:420] 找 A 白边、r[420:450] 找 B 黑线，并加 bv<40 确认黑线有效 排除 B 框内白卡（值 226–238）误判
多帧众数交叉验证 取 t=14/16/32/62/104/120/205s 共 7 个 SPLIT 时点重复测量 取值集合仅 [26]，零离散
Playwright DOM 几何 getBoundingClientRect() 返回原语数组（避免序列化循环引用崩溃） 渲染侧间距 −9px → +39px
中缝洁净度 + 背景自校准 从 stage 空白区取中位数作背景基准（非硬编码），6% 容差判断阴影是否填缝 实测背景 208（含 paper-grain 网点）
项原生 1280×7201080p 令牌此前的错误
A 框 left1624px写成 left:0 贴边
A 框 width392588px写成 31.1%（实为 30.63%）
中缝 gutter2639px被百分比与 padding 吃光
B 框 left434651px= 24 + 588 + 39
B 框 width8121218px写成 64%（实为 63.44%）
B 框右留白3451px写成 right:0 贴边
A 顶 / B 顶31 / 3946 / 58px误以为顶底对齐，实差 12px
叠压的三层根因 —— 只改一层都不够
① 百分比分栏：31.1% + 64% = 95.1%，剩 4.9% 给中缝，但百分比相对 stage 计算， 配上 left:0 + right:0 两侧贴边，中缝被两边同时挤压。
② box-sizing: content-box（默认值）：.frame-a 的 padding 与 .frame-b 的 border 都在 box 外额外撑开，把仅剩的缝隙吃光。
③ 阴影跨缝：即使 DOM 间距正确，A 框 51px 右阴影会把中缝染成 138–158（背景 209）， 肉眼仍然像粘在一起。
→ 修复：全部改绝对像素 + box-sizing: border-box + right: auto + 阴影收窄。 
# 中缝取证：同行双边界，7 帧零离散
seg = r[380:420]; w = np.where(seg >= 240)[0]
aR  = 380 + w.max() # A 框白边右缘
seg2 = r[420:450]; bL = 420 + int(np.argmin(seg2)); bv = int(seg2.min())
if aR and bv < 40:        # bv<40 确认命中黑线而非白卡
    gap = bL - aR - 1     # → 26，7 帧全部一致
阴影三轮迭代：为什么"只改窄一点"救不了中缝
· 右阴影 36px → 中缝像素 138–158，肉眼仍粘连；
· 右阴影 18px + B 左阴影 10px → 153–193，但纯背景像素 0/37 —— 两侧阴影在缝中相遇叠加；
· 定稿 A 右 10px + B 左 6px + A 框 padding-right:4px → 163→197，白边显现（254）， 中缝中段回归纯背景。
同时新增 --shadow-frame-a-full，让 FULL 场景保留实测那道 51px 厚重右阴影 —— 收窄只是 SPLIT 的局部妥协，不是推翻实测。

2 · 路由层：谁画这一镜

《教程.txt》的核心：生成之前先过一道判断门，能程序化就不抽卡。

镜头特征路由到理由
字幕、数字、卡片、图表、流程图、转场 Remotion 按帧精准、稳定、可局部编辑。慢两帧、字大了都能直接改
人物表演、空间变化、连续叙事 gpt-image-2.0图生视频 叙事与空间感是程序化的短板，只有这类才值得花视频生成额度
纸质拼贴质感（网点/机切边/纤维） gpt-image-2.0 物理材质细节手写 CSS 做不出来
产品录屏、功能演示 skip-generation 由原始素材承载，生成 UI mock 反而是编造
复杂 CSS 动效（clip-path/滤镜） HTML+CSSPuppeteer 录制 CSS 能力比 Remotion 内联样式更强的场合
省钱门（来自《教程.txt》）： 生成动画前先判断是否必须调用视频模型；出了问题先判断能不能用 Remotion 后期修， 能修就不重抽。构图/主体错了才重新生成，排版裁切问题一律本地修。

动态化规则

  • 从空的纯色纸场开始，先结构 → 后主体 → 再连接线 → 动作 → 结果

4 · 动效层：Remotion 精准控制

按帧可控是它唯一不可替代的价值。所有时间都换算成帧。

API用途本片参数
<Composition>注册可渲染视频 1920×1080 / 30fps / 7226 帧
<Sequence from= durationInFrames=> 把每个 Scene 钉在时间轴上由 SRT 时间码换算
useCurrentFrame()驱动一切动画—
interpolate()位移/透明度/图表生长 必带 extrapolate:'clamp'
spring()卡片入场、数字滚动 damping:100（去弹跳）
Easing.bezier()收尾克制的 ease-out (.22, 1, .36, 1)
<OffthreadVideo>嵌入数字人素材渲染更稳
<Audio>口播音轨与 SRT 对齐
// 标准入场：稳重、无弹跳（damping 拉到 100）
const enter = spring({
  frame, fps,
  config: { damping: 100, mass: 1, stiffness: 100 },
  durationInFrames: 12,          // 0.40s
});

// 逐行错开 4 帧（0.13s），一次只让眼睛读一行
const rowOpacity = (i) => interpolate(
  frame, [i * 4, i * 4 + 10], [0, 1],
  { easing: Easing.out(Easing.cubic),
    extrapolateLeft: 'clamp', extrapolateRight: 'clamp' }
);

// 打字机：每字 3 帧
const shown = text.slice(0, Math.floor(frame / 3));
const caret = Math.floor(frame / 15) % 2;   // 光标 0.5s 闪烁

为什么不用对称阴影

/* ✗ 大模型默认写法 —— 违背光照物理，一眼假 */
box-shadow: 0 4px 12px rgba(0,0,0,.1);

/* ✓ 本片写法 —— 左上光源，四边不等（实测 左16 右34 下32 上0）*/
box-shadow:
  -24px  0    24px -8px  rgba(60,44,24,.16),   /* 左 浅 */
   51px  0    40px -6px  rgba(60,44,24,.34),   /* 右 重 */
   0    48px 44px -10px rgba(60,44,24,.42);  /* 下 最重 */

5 · 数字人层：质心居中裁剪

用户要求 #1。关键在于按前景质心裁，不是按画面中心裁。

步骤技术判据
1 前景分离背景差分 / 人脸检测得到主体掩码
2 质心计算掩码一阶矩横向质心 cx
3 居中裁剪FFmpeg crop 令 cx 落在框宽 49.6%–53.5%
4 复核重测质心偏差 ≤ ±3.5% 才通过
# 按质心裁剪，而非 (iw-ow)/2
ffmpeg -i dh.mp4 -vf "crop=597:912:{cx-298}:{cy-456},scale=597:912" out.mp4

8 · 一句话总结

测量层定标准（39px 字幕、非对称阴影、两套画框）， 几何层定骨架（绝对像素、39px 中缝、两框绝不叠压）， 路由层定分工（能程序化就不抽卡）， 图像层定质感（先出图再出片）， 动效层定节奏（3.2s 中位镜长、SPLIT↔FULL 交替）， 合成层定收口（同一套脚本回测成品）。
审美不是加法，是章法。
而章法的第一条是：凡肉眼判断的，一律不可信 —— 量到零离散为止。
