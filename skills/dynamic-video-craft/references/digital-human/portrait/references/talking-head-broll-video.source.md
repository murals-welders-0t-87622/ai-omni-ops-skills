# 数字人 + B-roll 混剪长视频制作流程

把一段口播（数字人素材 + 音频 + SRT）做成「数字人 + B-roll 混剪」的知识付费风格长视频。

**成片以用户需求为准。** 参考片、教程文档、审美文档的作用是建立**业务流程与审美标准的基线**，
不是复刻目标。参考片提供的是"这类视频为什么好看"的可测量依据（栏宽节奏、边框阴影质感、
字幕比例、镜长分布），拿来当**默认值与质量下限**；用户明确要求不同时，一律按用户要求走。

---

## ⛔ 第零条：执行纪律（优先级高于本文档其余全部内容）

这一节是**用户明确下达的硬性纪律**，凌驾于所有技术判断、成本考量、时间压力之上。

### 0.1 禁止擅自降级

**"做不到就简化"是本技能历史上代价最大的失败模式，已发生多次，一律禁止。**

具体禁止的降级行为（每一条都真实发生过）：

| 禁止的降级 | 真实后果 |
|---|---|
| 分镜表点名 40 种组件，只实现 5 个通用模板 + 兜底 | 60 镜长得一模一样，用户评价"非常拉垮" |
| 预览页手写精致组件，生产环节另写"批量简化模板" | 生产页富度只有预览页 18%，一个确认过的效果都没进成片 |
| 分镜表要求 AI 视频镜，静默改成 HTML 动效 | 用户质问"怎么能擅自不按照要求来呢？也不和我说" |
| 门禁不过就放宽阈值 / 删掉断言凑通过 | 实测事实被抹掉，问题带进成片 |
| 组件难实现就换成近似的简单组件 | 分镜表失去约束力，等于没写 |
| 素材缺失就跳过该镜 | 成片出现内容断层 |

**遇到"做不到"时的唯一合法路径**：

1. 先穷尽技术方案（换实现路径、换工具通道、拆解为更小步骤）
2. 仍不行 → **立刻明确告知用户**：卡在哪、试过什么、有哪些备选方案及各自代价
3. **等用户裁决**，由用户决定降级还是换路
4. ✘ 绝不允许：自己拍板简化 → 继续往下做 → 不告知 → 等用户自己发现

> **纪律的本质**：降级本身不是罪，**不告知就降级**才是。
> 用户可以接受"这条路走不通，建议改用 X"，绝不接受"我悄悄换成了 X"。

### 0.2 禁止不按业务流程执行

阶段 0 → 1 → 1b → 1c → 2 → 3 → 4 → 5 → 5b → 6 → 7 的顺序**不可跳、不可并、不可倒**。

三道**不可逾越的闸门**：

| 闸门 | 位置 | 规则 |
|---|---|---|
| **配置确认闸** | 阶段 5b 之后 | 五件套 + 动态预览页交付用户，**拿到明确确认**才准进阶段 6 |
| **门禁闸** | 阶段 6 渲染前 | 六道门禁全绿才准渲染。渲染 65 镜约 15 分钟，骨架版渲成片再返工等于白烧两轮 |
| **并排目视闸** | 阶段 7 交付前 | 机械断言全绿后，**必须**抽 5 镜与预览页并排对比。机械断言能挡住"错"，挡不住"平庸" |

不许因为"用户在等"、"这镜看起来没问题"、"上次跑过了"而跳过任何一道。

### 0.3 默认不使用 AI 生成图片与视频（用户明确指令）

**B-roll 一律走本地零成本形式**：HTML 动效、静态卡片、打字机文字、数据动画、
拼贴图（本地合成）、现成视频素材、功能演示录屏。

- ✘ 不调用 `gpt-image-2.0` 出图
- ✘ 不调用 RunningHub / MiniMax H3 等文生视频、图生视频通道
- ✘ 不使用内置 `ImageGen` / `VideoGen` 工具

**唯一例外**：用户在当次对话中明确要求生成 AI 图/视频。此时才走
`references/AI-ASSET-CHANNEL.md` 记录的通道与纪律（并发=1 串行、先查已有成功记录、
提交前必读 `nodeInfoList` 模板、图生视频不可用时先问用户再决定是否转文生视频）。

> 本条是**默认值变更**，不是能力删除。历史上踩过的 AI 通道坑全部保留在
> `references/AI-ASSET-CHANNEL.md`，供例外情况查阅，避免重新试错。

### 0.4 遇到判断分歧时的裁决顺序

```
用户当次明确指令  >  本文档第零条  >  用户历史指令  >  分镜表  >  本文档其余章节  >  参考片  >  我的技术偏好
```


### 参考片的正确用法（阶段 0/1 的前提）

| 该做 | 不该做 |
|---|---|
| 量出边框/阴影/字幅/镜长，作为**起始默认值** | 把参考片的镜序、文案、配色照搬成成片 |
| 学它"为什么不呆板"（顶底错位、非对称阴影） | 把某一次实测数值当成放之四海的常量 |
| 用它的镜长分布校准节奏 | 用户已给出需求时还去追求"像素级一致" |

> 本文档中出现的所有具体数值（588px/39px/68% 等）都是**某一次参考片的实测记录**，
> 用于示范测量与反解方法。新项目必须重测，或直接按用户指定的版式设计。


## 铁律（违反其一即返工）

1. **用户需求优先于参考片**。参考片只提供默认值和质量下限。任何"参考片是这样的"都不能
   压过用户明确说出的要求；两者冲突时按用户要求做，并在 `DESIGN.md` 注明偏离原因。
2. **数值必须先量后做**。凡是要沿用参考片的观感（画幅、字号、边框、阴影、栏宽、镜长），
   数值必须来自**逐像素测量**，不允许目测、不允许凭经验假设。测量前先 `ffprobe` 确认真实分辨率——
   若参考是 720p 而成品做 1080p，所有像素值必须乘 1.5，忘了这一步会导致字幕大 3.6 倍这类灾难。
3. **配置文档必须先给用户确认**。`DESIGN.md` / `design-tokens.css` / `STORYBOARD.md` / `demo.html`
   / **动态预览页**五件套完成 → 跑机械自查 → 提交用户 → **拿到明确确认后**才允许出图、渲染、烧钱。
4. **HTML demo 里的示例文字绝不可以当成内容来源**。分镜屏显文本只能来自旁白原文或用户提供的资料。
   图表数字不得编造，没有数据就不画图表。
5. **B-roll 背景不允许纯白**，必须用暖米色纸质底。画面不允许空一大片。
6. **B-roll 形式必须 ≥5 种**。七种**零成本**可选形式（见阶段 4），**不要求全部用到**，但少于 5 种即视为
   表现力不足需返工。**优先复用工作空间已有 / 用户提供的视频素材**——先扫目录，能用现成的
   就用现成的。
7. **不使用 AI 生成图片与视频**（见第零条 0.3）。所有 B-roll 用本地手段实现：
   HTML 动效 / 卡片 / 打字机 / 数据动画 / 本地拼贴 / 现成素材 / 录屏。
   仅当用户当次明确要求时才走 AI 通道。
8. **分栏几何一律绝对像素**。A/B 两框之间必须有实测宽度的可见中缝，禁用百分比宽度、禁用
   `left:0`+`right:0` 贴边写法、必须 `box-sizing: border-box`、阴影不得越过中缝。
   改完必须用 Playwright 渲一帧，在**渲染像素**上确认中缝干净——DOM 间距对了不代表肉眼看着分开。
9. **肉眼判读永远不能推翻数值证据**。压缩后的截图不足以判断"偏左/偏右"。
   要推翻一个测量结论，只能用**另一条独立维度的测量**，不能用感觉。
10. **每种布局各标一套裁剪锚点**。A 框在 SPLIT（竖长）和 HERO（矮宽）下几何完全不同，
   同一个 `object-position` 百分比在两处结果相反。
11. **数字人素材必须按音频段绑定，不许按镜序轮转**。先确认数字人覆盖了哪几段口播——
   未覆盖的段本就是纯 B-roll。用 `DH[i % len(DH)]` 之类的轮转会让唇形与旁白全程错位，
   成片直接作废。时间轴 JSON 是唯一真源，页面生成、渲染、合成三方共用同一份。
12. **★ 预览页就是生产页，不是效果提案**。给用户看的动态预览页与最终渲染的合成页
   **必须共用同一份组件 CSS、同一段组件 HTML、同一组 `@keyframes`**。
   预览页只多一层 `.viewport/.scaler` 缩放壳与 HUD 控制条 —— **去掉壳就是生产页**。
   ✘ 严禁另写一套"批量生成用的简化模板"。用户确认的是预览页那个效果，
   交付骨架版等于交付了另一件东西 —— **这是本技能最容易犯、代价最大的错误**。
   机械自查：`生产页 DOM 节点数 ÷ 同题材预览页 DOM 节点数` 必须 ≥ 0.8，
   低于即判定生产页被简化，返工。
13. **★ 分镜表的「组件」字段是硬约束，不是备注**。分镜表逐镜写的
   `broll-hero.big-number`、`broll-thinking.compare-table` 这类组件名，
   **必须逐个实现，并在页面上留下可断言的 class 痕迹**。
   ✘ 严禁"实现 5 个通用模板 + 其余全部走兜底分支"。分镜表通常点名 30–40 种组件，
   兜底分支会把几十镜压成同一个模样，而且**这种失败几何断言与像素统计都测不出来**
   （几何合法、颜色正确、动画在动，唯独内容是空的）。
   必须跑组件覆盖率断言：分镜表点名的组件 **100% 在页面上找到对应 class**，
   任何一镜落进兜底即 FAIL。
14. **★ 富度必须机械设下限**。每镜同时满足：B 框内 DOM 元素 ≥ 12、
   页内 `@keyframes` ≥ 2、`getAnimations()` ≥ 3，且 B 框内不允许
   "单个 `<video>` 铺满 + 两行小字"这种零信息版式。任一项不达标即 FAIL，
   **禁止进入渲染**。渲染是不可逆的时间成本（65 镜一轮 11 分钟），
   把骨架版渲成片再返工等于白烧两轮。
15. **★ 富度基线必须对齐预览 demo**。用 5 个动态预览页的 DOM 中位数作为
   该镜型的富度基线，生产页 `ratio = DOM / 基线 DOM` 必须 ≥ 0.8。
   只看"B 框 DOM ≥ 12"会被装饰性空节点骗过，ratio 才能拦住"页面被整体简化"。
16. **★ 补层必须是真实信息，不能堆装饰**。缺 DOM 时禁止随手加星星/线条/色块充数，
   必须回到分镜表 `screen` 字段读语义：冰山图就补 7:3 占比 + 水位刻度；
   循环图就补圈数计数 + 12 个环刻度；图表无 tip 就补端点读数。
   装饰元素能过门禁但会毁掉"信息密度"，用户一眼就能看出来空。
17. **★ 对照版式的中轴必须实体化**。`c_versus` 类的左右对比不能只写"VS"文字，
   必须做成上下两条渐变轴线 + 中间圆形徽章，轴线高度随内容自适应。
   文字中轴在视觉上站不住，是造成"对照页很空"的直接原因。
18. **★ 图表必须有轴刻度和端点标注**。Y 轴高低标注、X 轴分度线、端点读数
   不是装饰，是图表的本体信息。`_chart()` 无数据提示时必须补端点标注，
   否则一条光杆折线再过门禁也显得没内容。
19. **★ 通用补层三件套优先复用**。跨组件统一使用：`.b-kicker .meta` 页眉元信息、
   `.note-strip` 图形标注条、`.rule-strip` 底部刻度尺。单手段可提升 DOM 5–21 个，
   而且承载的是真实语义（步骤、要点、进度），不是装饰。
20. **★ 同一字段的解析逻辑只能有一份**。分镜表 `component`、`screen`、`form` 等字段
   绝不允许生成器写一套正则、门禁写另一套。`_rich_check.norm_comp()` 与
   `_gen_rich.comps_of()` 必须使用完全相同的白名单正则，否则会出现
   "生成器正常、门禁误报未登记组件"的互相矛盾。
21. **★ 回声页（skip 镜）要有独立判据**。跳过镜不是"没内容"，是沿用前镜末态的
   特殊镜型。不适用普通 DOM ≥ 12/35 下限，单独设 `ECHO_DOM_MIN=20`，
   并在 `.stage` 上打 `.echo` 类由统一 CSS 提供样式。`.echo` 必须打在 stage 上，
   不能由页面内嵌 style 注入。
22. **★ 确定性 seek 必须区分 CSS 动画与 `<video>` 两种方案**。
   CSS 动画用 Web Animations API：`pause()` 后写 `currentTime`，无限循环动画
   必须对 duration 取模；`<video>` 必须叠加 `data-off` 偏移，seek 后等待 `'seeked'`
   事件，素材短于需求时 `% duration` 回绕。两套机制混用会出黑帧/末态定格。
23. **★ B-roll 卡片与文字本身禁止位移/缩放/飘动**（2026-08-11 东哥指令）。
   卡片不 float、不 pulse、不做缩放呼吸；标题不做大字缩放；文字不做上下飘移。
   画面要"活"，只能靠**卡片内部的功能性微动元素**：图表线条流动/描边偏移、
   数据滚动、图标呼吸、进度条、扫描线、箭头、印章盖落等"元素自身"的微动。
   同时卡片元素必须**丰富饱满**——主文案 + 图标块 + 指标块 + 标注条等多元素组合，
   禁止"干巴巴一行文字 + 一张卡"的稀疏版式。
24. **★ 禁止使用「背景忽明忽暗」类全屏亮度动效**（2026-08-12 东哥指令，一票否决）。
   全屏 vignette 暗角呼吸、全屏透明度/明度脉冲、整体亮度循环——一律禁用。
   这类效果机械门禁数值好看，但肉眼观感是"背景在闪"，属于"为了动态而动态"。
   动态度不足的正确解法永远回到铁律 23：**给卡片内补真实微动元素**，
   不是给全屏打闪光灯。
25. **★ 需被逐帧渲染捕获的动效，载体必须是真实 DOM 元素 + 纯 CSS @keyframes**。
   `feTurbulence` 等 SVG 噪声数据 URI 在 headless Edge/Chrome 中**不渲染**；
   `::before`/`::after` 伪元素动画虽能被 `document.getAnimations()` 捕获，
   但 5fps 抽帧采样易与动画周期对齐产生 aliasing（frozen 误判/采样全同相）。
   因此保底/测量相关动效一律写在真实元素上，用位移/透明度/描边偏移等
   纯 CSS 属性，禁高频噪声、禁伪元素兜底。

## 执行顺序

### 阶段 0 · 需求对齐 + 素材盘点 + 参考基线探测

**先问清需求再动手**：成片时长/画幅、数字人在左还是右、是否允许换位、字幕语言、
是否有必须出现的品牌元素、有没有参考片。**参考片可选**——没有就按 `DESIGN-example.md`
的默认基线走。

盘点手头资源（决定 B-roll 形式配比的前提）：
```bash
ls *.srt *.mp3 *.wav 2>/dev/null                    # 旁白 + 时间轴
find . -iname "*.mp4" -o -iname "*.mov" | head -50  # 可复用视频素材
```

若有参考片，探测其真实规格（否则跳过阶段 0/1 的测量部分）：
```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,r_frame_rate,nb_frames \
  -show_entries format=duration -of default=nw=1 参考.mp4
```
把 `width×height` 写进笔记。后续所有测量值都以**原生像素**记录，
成品分辨率不同时统一乘 `scale = 成品宽 / 参考宽`（例：1920/1280 = 1.5）。

### 阶段 1 · 逐像素测量
跑 `references/measure-frames.py`（改顶部 `SRC` 指向参考视频），产出：
- 背景色（多帧众数）
- 画框边框：一维亮度剖面 `row = img[y].mean(axis=1)` 逐像素打印，1px 精度定位边界
- 阴影四向衰减：分别沿左/右/上/下扫，记录扩散距离与最深处相对背景的差值
- 布局节奏：列投影聚类 → FULL / SPLIT / WIDE / MULTI 段落时长分布

跑 `references/measure-subtitle.py` 单独测字幕（**必须独立测**，否则会被卡片白块污染）：
- 只取画面中段横向窗口（避开左右卡片）
- 双条件掩码：`白>232` **且** `描边<105`
- 从底部向上扫，取**最下一个**连续块 → 得字高、距底、中心 x

> 两个脚本都把 stdout 重定向到 utf-8 日志文件，避免 Windows 控制台中文编码导致静默失败（退出码 1、0 字节输出）。

### 阶段 1b · 分栏几何取证（★ 最容易翻车的一步）

分屏版式**绝不能靠百分比估算**。必须把 A/B 两框的四条边全部量成绝对像素，尤其是**中缝宽度**。

跑 `references/measure-geometry.py` 与 `measure-geometry-multiframe.py`：
- 同一行同时定位 A 框白边右缘（`>=240`）与 B 框黑描边左缘（`<=40`），差值即中缝
- **必须限定扫描窗**（如 `r[380:420]` 找 A 白边、`r[420:450]` 找 B 黑线），否则会把 B 框内部的
  白色卡片（值 226–238）误判成 A 框白边，同一时间点会给出 `-2 / -32 / 27 / -135px` 这类互相矛盾的值
- 加 `bv < 40` 断言确认真的命中了黑线
- **多帧众数交叉验证**：取 8–10 个 SPLIT 时点重复测量，取值集合应收敛为单一值（零离散）

必须产出这张表（本次参考视频实测，新片需重测）：

| 项 | 原生 | ×1.5 | 陷阱 |
|---|---:|---:|---|
| A 框 left | 16 | 24px | **不是 0**，A 框并不贴边 |
| A 框 width | 392 | 588px | 30.63%，不是 31.1% |
| **中缝 gutter** | **26** | **39px** | ★ 两框分离的唯一视觉证据 |
| B 框 left | 434 | 651px | = 24 + 588 + 39 |
| B 框 width | 812 | 1218px | 63.44%，不是 64% |
| B 框右留白 | 34 | 51px | **不是 0** |
| A 顶 / B 顶 | 31 / 39 | 46 / 58px | 顶底各错位 12px，**不是对齐的** |

> A/B 顶底刻意错位 12px，是参考视频"看起来松弛不呆板"的隐形来源。做成对齐反而会显得死板。

写 CSS 时三条铁律（写进 `DESIGN.md` 的 NEVER 段）：
1. 分栏宽度**只用绝对像素**，禁用百分比
2. 两个 frame 必须 `box-sizing: border-box`
3. A 框右阴影 + B 框左阴影之和 **≤ 中缝的一半**

改完跑 `references/regress-geometry.py`（含"是否偷偷改回百分比"的反悔检查），
再用 Playwright 渲一帧跑 `references/verify-gutter-render.py` 验证中缝在**渲染像素**上确实干净。

### 阶段 1c · 数字人裁剪锚点标定（★ 三条独立证据交叉验证）

数字人源帧是横构图（如 1280×704），A 框是竖长框（如内容区 575×872）。
`object-fit: cover` 会**横向裁掉约 64%**，默认 `center` 取源图正中——
但人物几乎从不站在源图正中，于是成品里人明显偏一侧。这是"数字人不居中"的唯一根因。

**必须实测人体中心，不许目测。** 且单一方法一定会翻车，必须凑齐**互不相关的三条证据**：

| 证据 | 脚本 | 维度 | 抗干扰性 |
|---|---|---|---|
| 亮度质心 | 亮度 75 分位 + Sobel 加权 | 亮度 | ❌ 影棚侧补光会把质心拉偏 |
| 阈值包围盒 | 5/98 分位自校准 + 列投影 | 亮度 | ❌ 会抓到灯架/背景板等固定亮物 |
| **帧间差分** | `references/anchor-motion-diff.py` | **运动** | ✅ 相机固定，只有人在动 |
| **肤色检测** | `references/anchor-skin-detect.py` | **色度** | ✅ 灯架/反光板通不过肤色规则 |

**收敛判据**：两条独立维度的结论若落在 1 个百分点内即可定案；
若某条方法给出的边界值在多帧间**零抖动**（如左边界恒为 243），那是背景固定物，**该条证据作废**。

帧间差分核心（不依赖任何亮度阈值）：
```python
d = np.maximum(np.maximum(np.abs(a2-a0), np.abs(a1-a0)), np.abs(a2-a1))
thr = max(6.0, float(np.percentile(d, 99.0)) * 0.30)   # 自适应，不写死
m = d > thr
```

Kovac RGB 肤色判据：
```python
m = ((R>95)&(G>40)&(B>20)&((mx-mn)>15)&(np.abs(R-G)>15)&(R>G)&(R>B))
```

两者都只取**头肩带** `mask[0:int(h*0.55), :]`——实测头肩极差 3.2，全身极差 8.6
（手臂动作会污染全身中心），**以头肩为准**。
同时用「加权中心」和「包围盒中点」两个指标自查，差值应 <0.01。

拿到人体中心 `cx` 后，用 `references/anchor-solve-objx.py` 反解 `object-position`：
```python
scale = max(BOX_W/src_w, BOX_H/src_h)
overflow_x = src_w*scale - BOX_W
p = (cx*src_w*scale - BOX_W/2.0) / overflow_x   # 结果 ×100 即百分比
```

**每种布局必须单独反解**（铁律 8）。本次实测：

| 布局 | A 框内容区 | 可裁量 | 理论解 | 落盘 |
|---|---|---:|---:|---|
| SPLIT | 575×872（竖长） | 1010px | 68.0% | `object-position: 68% center` |
| HERO | 428 宽时 415×261（矮宽） | 59.5px | **140.5% 够不着** | 把框收窄到 353px → 90% |

> HERO 布局横向可裁量不足时，**不要硬塞百分比**（会被 clamp 到 100% 仍不居中），
> 正确做法是**收窄 A 框**换取可裁量，并留 10% 余量——取 100% 死顶边界的话，
> 换一帧人物微动就立刻失效。

**纵向是死参数**：`scaled_h = src_h × scale` 常常正好等于 `BOX_H`（溢出为 0），
此时 `object-position` 的纵向分量完全无效。若头顶留白不足（实测 `head_top` 中位数 0.034，
理想 0.06–0.16），那是**源素材本身头贴顶**，只能换帧或缩放，改 CSS 是无效动作。

落盘后必须跑 `references/preview-center-verify.py` 做**渲染后像素级复验**：
截真图 → 在 A 框内跑同一套肤色检测 → 算人物中心相对框中心的偏差，
容差 ±5%（换算到 575px 框约 ±29px）。数学推导不算数，渲染像素才算数。

裁剪锚点的注释必须写清**证据来源**，禁止写"已按前景质心预裁"这类无法追溯的空话：
```css

/* 源帧 1280×704 未预裁；68% 由帧间差分（6 片段中位 68.0%/极差 3.2）
   与肤色检测（18 帧中位 68.7%/极差 5.6）双重实测反解 */
```

关键结构性认知（本次参考视频的实测结论，新片需重新验证）：
- **两套画框系统并存**：数字人框是厚白内边框；B-roll 框只有极细黑描边、无白边。别用同一套 CSS 糊过去。
- **阴影四向非对称**：下 > 右 > 左 > 上（上边可能为 0）→ 光源在左上方。
  必须写成三段 `box-shadow` 分别控制左/右/下，不能用对称 blur。

三旋钮（取自 taste-skill）在文档 §0 显式声明取值：
`DESIGN_VARIANCE`（版式变化度）/ `MOTION_INTENSITY`（动效强度）/ `VISUAL_DENSITY`（信息密度）。

### 阶段 5b · 动态 HTML 预览页（★ 提交用户前的最后一关）

`demo.html` 是静态单帧，**看不出节奏、动效时序、入场顺序有没有问题**。
必须再做一组**可播放的动态预览页**，让人在浏览器里真的"看一遍"再决定要不要开始烧钱。

> **★★ 首要前提：这一步不是做"效果提案"，是在建立生产组件库。**
> 预览页里手写的每个组件（卡片网格、大数字、面积图、类比图、决策树…）
> 都必须写进一份**共用组件 CSS**（如 `_components.css`），
> 阶段 6 的生产页 **`@import` 同一份文件、复用同一段组件 HTML**。
> 预览页 = 生产页 + `.viewport/.scaler` 缩放壳 + HUD 控制条，**仅此差别**。
>
> 落地方式（二选一，推荐前者）：
> - **组件片段化**：每个组件写成独立的 HTML 片段文件（`components/card-grid.html` 等），
>   预览页与生产页都 include 它，物理上不可能出现两套实现。
> - **生成器统一**：预览页也由生产用的生成器产出，只是多传一个 `preview=True`
>   开关来套壳。
>
> ✘ 反面案例（真实事故）：预览页手写了 5 个精致镜头（DOM 节点 43–65、
> keyframes 2–9），用户确认后，生产环节另写了 5 个通用模板批量生成 65 页
> （DOM 节点 5–18、页内 keyframes 0）。**生产页富度只有预览页的 18%**，
> 一个预览效果都没进成片。用户看到成片的反应是"非常拉垮"。

产出结构（照抄 `references/preview-*` 系列）：

```
previews/
  index.html          # 目录页：卡片式导航 + 每页一句话说明
  _shell.css          # 仅放 1920×1080 舞台缩放壳 + HUD 样式（不放组件样式！）
  _components.css     # ★ 全部组件样式 + @keyframes —— 生产页共用这一份
  _shell.js           # 时间轴驱动、进度条、重播、键盘控制
  p1-....html ~ p5-....html   # 5 个代表性镜型，各自可独立打开
```

设计要求：
- **每页覆盖一种不同镜型**（SPLIT / FULL / HERO / WIDE / MULTI），不要 5 页都是同一个版式
- 舞台固定 1920×1080，外层用 `transform: scale(k)` 自适应窗口；
  **所有几何写死绝对像素**，绝不因缩放而改变比例
- 动效走纯 CSS `@keyframes` + JS 时间轴，不引外部库，单文件可离线打开
- 三个可截图的时间锚点：`a-enter`（入场中）/ `b-mid`（主体展示）/ `c-settle`（稳定态）
- 每页顶部标注镜号、旁白原文、用到的动效名——方便用户指着说"第 3 页那个不对"
- **★ 组件样式一律写进 `_components.css`，不写在页面 `<style>` 里**。
  写在页内的样式生产页拿不到，这正是断层的物理来源。

机械自查（`references/preview-geometry-check.py`）：
- Playwright 打开每页，在三个时间锚点各截一张图
- 用 `getBoundingClientRect()` 断言 A/B 框绝对几何与中缝宽度
- **★ 陷阱**：舞台被 `scale(k)` 缩放过，`getBoundingClientRect()` 返回的是**屏幕像素**，
  必须 `÷k` 才回到 1920 设计坐标系。断言失败时先怀疑断言忘了除 k，
  原则是**修断言、不改页面**——页面几何是实测事实。
- HERO 等居中布局额外断言左右留白相等（如 783.5 + 1136.5 = 1920）
- **★ 记录每页 DOM 节点数与 keyframes 数，写进 `_preview_baseline.json`**。
  这是阶段 6 富度门禁的比对基线，没有它无法判断生产页是否被简化。

再跑 `references/preview-center-verify.py` 复验数字人居中（见阶段 1c）。

全绿后用 `present_files` 把 `index.html` + 5 个页面 + 截图一起交付，
并明确告知"确认后才开始出图渲染"。**用户没点头，不许进阶段 6。**

> 全页截图缩到对话里会看不清细节。要核验裁剪居中这类细节，
> 用脚本**裁出 A 框区域原尺寸单独出图**，不要指望全页图。

### 阶段 6 · 生产（仅在用户确认后）

**6.0 先建权威时间轴，别急着生成页面**（★ 跳过这步等于全片重做）

音频段 → 镜头 → 数字人素材 的映射必须先落成一个 JSON，后续所有脚本共用：

- **数字人可能只覆盖部分口播段**。先查生成脚本里的段名清单（如 `SEGS = ['p1a','p1b','p3a',...]`）
  和实际 `dh_*.mp4` 个数。若 P2/P4 没有对应素材，**这些段本就设计为纯 B-roll**。
  绝不能用 `DH[i % len(DH)]` 按镜序轮转 —— 那会把 P1 的唇形配到 P4 的旁白上，
  错位时长 = 无素材段总长（实测一次错 111s，整片是废片）。
- **SRT 标称轴与音频真实轴会漂移**。取 `K = 音频总长 / SRT总长`，
  所有镜头时间码与 cue 时间码统一乘 K（实测漂移 3.72s，正是音字不同步的根因）。
- 每镜记录 `dh_offset = 镜头起点 - 所属音频段起点`，并钳制 `min(off, 素材时长 - 镜长)`
  避免数字人视频短于音频时出黑帧。
- 校验三项：时间码断点数 = 0、成片总长与音频总长差 < 0.01s、偏移+镜长越界镜数 = 0。

**6.0b 分镜表解析的两个必踩坑**

- `re.split(r'^### (S\d+) · ')` 后**最后一镜的 body 会吞掉文末所有章节**。
  若自查表里出现过 `skip-generation` 字样，末镜会被误判为跳过镜（实测丢了收尾板）。
  必须先 `body = re.split(r'^## ', body, flags=re.M)[0]` 截断。
- `skip` 只认「生成状态」字段，不要用全文 `in body` 匹配。
- 跳过镜常写成一行双字段 `composition_src：无 · **track**：无`，
  `(.+)` 会贪婪吞整行导致 src 非空。取值时先 `.split(' · ')[0]`。

1. 生成 `compositions/scene-XX-*.html`，全部 `@import` 同一份 `design-tokens.css`
   **以及阶段 5b 建好的 `_components.css`**。
2. 数字人裁剪：直接复用阶段 1c 标定好的 `object-position`，**每种布局用各自那一套**。
3. B-roll 按分镜表逐镜生成，**优先级**：复用现成视频素材 > HTML 动效/卡片/打字机/数据动画 >
   本地拼贴 > 录屏。**不走 AI 生成通道**（第零条 0.3）。

**★★ 3a. 生成器必须逐个实现分镜表点名的组件，禁止兜底吞并**

这是**本技能最高频、危害最大的失败模式**，务必按下面的顺序做：

1. **先统计分镜表点名了多少种组件**：
   ```python
   c = collections.Counter(s['component'] for s in SB)
   print('点名 %d 种 / %d 镜' % (len(c), len(SB)))
   ```
   实测一个 65 镜的片子会点名 **40 种**组件（`broll-hero.big-number`、
   `broll-charts.area-chart`、`broll-thinking.compare-table`、`broll-flows.swimlane`…）。
2. **按「组件名 → 渲染函数」建注册表**，而不是按「形式关键词 → 5 个通用模板」：
   ```python
   REGISTRY = {
       'broll-hero.big-number':        tpl_big_number,
       'broll-hero.big-type':          tpl_big_type,
       'broll-charts.area-chart':      tpl_area_chart,
       'broll-thinking.compare-table': tpl_compare_table,
       ...   # 点名的每一种都要有
   }
   def build(sid):
       key = norm(SB[sid]['component'])
       if key not in REGISTRY:
           raise SystemExit('[FAIL] %s 的组件 %s 未实现' % (sid, key))  # ★ 硬失败
       return REGISTRY[key](...)
   ```
   **注册表缺项必须让脚本硬失败退出**，绝不允许 `return tpl_generic(...)` 兜底。
   宁可脚本跑不完、逼自己去补组件，也不要静默产出 60 个同款骨架页。
3. **一镜写多个组件时全部实现**（如 `broll-hero.big-number + broll-charts.area-chart`
   要求同页既有大数字又有面积图），用 `+` 切分后逐个渲染再拼版。
4. 组件实现顺序：**先把阶段 5b 手写的 5 个直接搬过来**（它们已被用户确认），
   再按点名频次从高到低补齐其余。

**★★ 3d. 六道机械门禁 —— 全绿才准渲染**

几何断言只能证明"框没画错"，像素统计只能证明"有颜色在动"，
**两者都无法发现"页面内容是空的"**。必须跑齐下面六道，脚本已在 `references/`：

| # | 门禁 | 脚本 | 拦住什么 | 判据 |
|---|---|---|---|---|
| 1 | **富度** | `gate-rich-check.py` | 页面被整体简化 | B框 DOM ≥12、`getAnimations()` ≥3、`@keyframes` ≥2、`ratio ≥ 0.8` |
| 2 | **组件覆盖** | `gate-comp-check.py` | 组件落进兜底分支 | 分镜表点名组件 **100%** 命中 class；含版式几何断言 |
| 3 | **图表比例** | `gate-chart-probe.py` | 图表压扁 | 实际AR / viewBoxAR ≤ 1.35 |
| 4 | **遮挡** | `gate-occlude-check.py` | 文字被数字人小窗压住 | 任一文字元素被遮挡面积 = 0 |
| 5 | **文字可读性** | `gate-text-probe.py` | 文字在暗底上看不清 | 每个文字块 Δ(墨/底) ≥ 100 |
| 6 | **纸幕遮盖度** | `gate-scrim-probe.py` | 视频层透穿或纸幕过重 | 达成率 ≥ 80%（相对理论上限） |

**门禁纪律（★ 违反即返工）**：

- ✘ **不许放宽阈值凑通过**。阈值来自实测，改阈值等于抹掉实测事实。
- ✘ **不许删断言凑通过**。令牌搬家导致旧断言过期时，把断言**跟着搬**并补新约束。
- ✘ **不许"这镜特殊所以跳过"**。真的特殊镜型（如回声页）要有**独立判据**
  写进脚本（`ECHO_DOM_MIN=20`），而不是从检查列表里摘出去。
- 六道全绿只是**准入条件**，不是交付条件。还要过阶段 7 的并排目视闸。

**★ 门禁脚本的读法（血泪教训，必须照做）**

`gate-rich-check.py` / `gate-comp-check.py` / `gate-chart-probe.py` /
`gate-occlude-check.py` / `gate-scrim-probe.py` 都把 `sys.stdout` 重定向到 `.log`，
前台跑**终端零输出且 exit=0**，极易误判成"脚本没执行"。固化读法：

```bash
python gate-rich-check.py; echo "exit=$?"; tail -30 _rich_check.log
```

`gate-text-probe.py` 是例外（只重设编码不重定向），可前台直接看输出。
**读之前先 `grep -n "sys.stdout" 脚本名` 确认属于哪一类。**

**★ 门禁报警必须用「单镜双模对照」复核，不能直接照批量结果改全局**

批量探针与单镜跑的抓帧时刻不同，会产生偶发差异。实测案例：批量报
S28「文字 LOW 1→2（新增 1）」，单镜双模对照发现**含视频与基线都是 1 处，增量实际为 0**。

**判据永远是「含视频 LOW 数 − 基线 LOW 数」的增量**（`--base` 开关切基线模式）。
基线本身就不合格的元素属于设计问题，不该记在视频头上 —— 但仍然要修。


```python
# Playwright 打开每页，在 t = dur*0.6 处采样
n_dom   = 页面 .frame-b 内 querySelectorAll('*').length
n_anim  = document.getAnimations().length
n_kf    = CSS 文本里 @keyframes 出现次数
hit     = 分镜表点名组件对应的 class 是否在 DOM 中找到
ratio   = n_dom / 预览页基线同镜型的 n_dom      # 读 _preview_baseline.json
```

判定（任一不过即 FAIL，**禁止进渲染**）：

| 断言 | 门槛 | 拦住的失败 |
|---|---|---|
| `n_dom` | ≥ 12 | "一个 video 铺满 + 两行小字"的零信息页 |
| `n_anim` | ≥ 3 | 页面完全静止，只有底层视频在动 |
| `n_kf` | ≥ 2 | 组件样式没被引入（写在预览页页内 `<style>` 里了） |
| `hit` | 必须命中 | 组件落进兜底分支 |
| `ratio` | ≥ 0.8 | 生产页整体被简化（实测出过 0.18） |

日志必须逐镜打印这 5 个数，并在末尾给出全片中位数与最小值 ——
**只看"失败项 0"不够，要看数值分布**：中位数掉到基线一半就是系统性简化。

**★★ 3e. 门禁报警的归因方法论（不许跳步直接调参数）**

门禁报出问题后，**必须先定位根因再动手**。历史上多次"按第一直觉改配色/加高度"
结果毫无变化，白烧一轮。三套归因法：

**(1) 文字对比度报 LOW → 三态判别**

先量 ROI 的 `min`/`max` 像素值，再分流（用 `diag-low-contrast.py`）：

| 观测 | 根因 | 修法 |
|---|---|---|
| `min=0` 且 max 很低 | **被遮挡** | 查 `elementsFromPoint` 图层栈 → 把元素挪走 |
| `min` 很高（如 156）、无暗像素 | **溢出画框** | 量到的是画框外页面底色 → 收装饰层 |
| min/max 跨度正常但 Δ 不足 | **真的配色问题** | 才轮到调墨色 |

> ✘ 反面案例：S31「7 : 3」Δ=15，按配色问题加了 `-webkit-text-stroke: 6px`
> + `paint-order: stroke` + 双层 `text-shadow`，**复测依然 Δ=15 毫无变化**。
> 量像素才发现 `min=0 max=15` 整块纯黑 = 被数字人小窗盖住。
> **不量像素就调颜色，等于闭眼开车。**

**(2) 配色问题的修法：「淡而不透」**

配角元素不该靠**半透明**表达，而应靠**墨色抬实 + 字重降低 + 字号略收**表达。
半透明会让暗视频直接透穿。

- S09 `.vs__t/.vs__s`：`.46/.42` → `.62/.60`，Δ 83/77 → 达标
- S28 `.an__eq`：`rgba(60,44,24,.34)/900/54px` → `.74/700/48px`，Δ 70 → 122

**(3) 遮挡的修法是「挪走」，不是「加底衬」**

底衬盖不住 `z-index:3` 的数字人小窗。`layout-full` 的 `.frame-a` 是
`right:72 / bottom:180 / 246×328` 的右下角画中画，实测占据 `x 1602~1848、y 572~900`
（10 个镜次逐一验证，几何值完全一致）。

- `.rule-strip b` → `order:-1` 挪到刻度尺**左端**（x 起点 ~92，余量 1500px，永久安全）
- SVG 轴标签 → 不能用 order 挪，**更不能给 svg 加 padding**
  （svg 是替换元素，padding 会压缩绘图区导致曲线变形 = 图表压扁老坑），
  正解是给外层 `.chart` 容器加 `padding-right`，svg 随容器等比缩窄，viewBox 比例不变

> 这类问题**在截图里根本看不出来**（那块就是数字人画面），
> 必须用 `gate-occlude-check.py` 做 DOM 几何关系机器检测。

**(4) `.b-pad` 绝不能加 `overflow: hidden`**

文字补底大量依赖 `box-shadow: 0 0 0 Npx` 做**外扩**底衬，
`hidden` 会把贴边元素的底衬整圈裁掉。溢出问题要从源头解决 —— 收起装饰层：
`.b-pad > .is-second ~ .note-strip ~ .rule-strip { display: none; }`

**(5) 探针指标反常时，先质疑指标本身**

`tex_keep`（纹理保留）在线性合成 `out = a×247 + (1-a)×src` 下满足
`std(out) = (1-a)×std(src)`，即 **`keep ≡ (1 - alpha)` 恒等于 45%**，
与素材、滤镜全都无关 —— 这个指标压根测不出它声称要测的东西。
用 numpy 网格搜索反推确认后，改用「达成率 = 实测/理论上限」判据，闸值 80%。

**3b. 纯 B-roll 段要多套全幅版式，不能一种铺到底**

无数字人的段若全用同一种 FULL，会出现连续十几镜同版式的呆板段落。
按内容形式分派 4 种（占画面比例差异要大）：金句/设问 → 宽幅居中；
结构图/表格/多节点 → 高幅；图表/数字滚动 → 横向窄带；拼贴/反白闪屏 → 满幅出血。
再加**反连续规则**：同版式连续到第 3 镜时强制换成几何差异最大的对位版式
（内容照旧，只改画框形状与留白）。进入有数字人段时重置连续计数。

**3c. 跳过镜（skip-generation）用「回声页」，不要定格前镜末帧**

若跳过镜落在**有数字人的音频段内**，定格末帧会让唇形停住而语音继续 —— 明显穿帮。
分镜表写「沿用前镜末态卡片渐隐」的真实含义是：B 框静置降透明度，**数字人继续说话**。
做法是克隆前镜页面后改四处：B 框内容降透明度并冻结动画、
`video[data-off]` 换本镜偏移、stage 的 data 属性换本镜、字幕 cue 换本镜时间窗。
冻结动画必须 `animation-play-state:paused` **配合** `animation-delay:-9999s`，
只写 paused 会停在首态而不是末态。

4. Remotion 渲染：`interpolate` 一律带 `extrapolateLeft/Right:'clamp'`；
   `spring({damping:100})` 去弹跳；视频层用 `OffthreadVideo`。

**4b. 若走 Playwright 逐帧截图路线（纯 CSS 动画，无 GSAP）**

- CSS 动画用 Web Animations API 钉进度：`document.getAnimations()` 逐个 `pause()`
  后写 `a.currentTime = t*1000`。**无限循环动画（如光标闪烁）必须对 duration 取模**，
  否则 currentTime 溢出后停在末态。
- `<video>` 用 `currentTime = data-off + t`，**必须等 `'seeked'` 事件而非 sleep 猜**；
  素材短于需求时 `target % duration` 回绕避免定格黑帧。
- Chromium 必须加 `--autoplay-policy=no-user-gesture-required`，否则 `<video autoplay>` 不解码。
- 字幕逐帧从 `data-cues` 取「起点 ≤ t 的最后一句」，静态只显示第一句会让长镜头字幕停住。
- 日志里断言 `video readyState`（应为 4）与字幕覆盖帧数（应等于总帧数）。

5. FFmpeg 合成 + 烧字幕，然后**用阶段 1 的同一套脚本回测成品**，
   成品测出的字号/边框/阴影必须与 tokens 一致。

**5b. 多段音频拼接不能用 concat demuxer**

多段 mp3 直接 `-f concat -c:a aac` 会在接缝处产生无效采样，
报 `Input contains (near) NaN/+-Inf` 并编码失败。
改 `filter_complex`：各段先 `aresample=48000,aformat=sample_fmts=fltp:channel_layouts=stereo`
解码为 PCM，再 `concat=n=N:v=0:a=1`。

**5c. 回测偏色前先查分镜表主色**

抽帧统计出的色调偏离基色时，先核对该镜在分镜表里指定的「主色」。
章节收束镜常故意用墨绿/青蓝等对比色，属设计意图而非渲染错误。

### 阶段 7 · 渲染 → 合成 → 交付验收

**7.1 渲染（`render-frames-css.py`）**

- 重渲染用脚本自带的 **`--force`** 开关，**不要试图删文件**。
  沙箱禁止删除（`rm` 拒相对路径、`os.remove` 被 `sitecustomize.py` 的 `_safe_remove` 拦截），
  实在要避让就 `shutil.move` 改名。

- 逐镜日志必须确认：`ok=N fail=0`、每镜**字幕覆盖帧数 = 总帧数**、`video readyState=4`。

**7.2 合成（`assemble-final.py`）**

```bash

```

- **★ 输出名绝不能硬编码**。写死 `final_v6.mp4` 会导致每次合成都**原地覆盖上一版**，
  新版出问题就没有对照物可退回。必须传版本号，且中间产物
  `_v65_<ver>.mp4` / `_a65_<ver>.m4a` / `_concat65_<ver>.txt` 与日志
  `_assemble65_<ver>.log` **一并带版本号**，避免多版并行互相踩。
  注意 `VER` 要在 `LOG` 之前解析。
- 四步顺序不可颠倒：**逐镜校验时长 → 拼视频轨 → 拼音频轨 → 合流**。
  先校验才能在源头拦住渲染问题，而不是拼完才发现不同步。
- 单镜时长误差门槛 0.12s（帧数取整误差为 1/30s，超 0.12 说明渲染有问题）。
- 音视频长度差应 < 0.5s，> 0.5s 必须回头排查而不是靠 `-shortest` 硬裁。

**7.3 交付前验收（三层，缺一层不许说"做完了"）**

**★ 目视验收不可靠，必须用像素统计做机器判据**

用 `Read` 直接看大 PNG 时图会被缩放，肉眼判断极不可靠。实测矛盾案例：
`fix_s07.png` 被读成「大面积噪点」，而 `gate-chart-probe.py` 独立测得
S07 图表宽 1496 / 畸变 1.07 完全正常 —— 两个结论互相打架。

`shot-health.py` 的三条判据必须一起看（缺一条都会误判）：

| 指标 | 正常区间 | 异常含义 |
|---|---|---|
| `mean` 整体亮度 | 150~250（纸艺底色 ~247） | `>252` 且 std 极小 = 页面没渲染出来 |
| `std` 明暗跨度 | ≥ 6 | `<6` = 画面几乎没内容（空白页） |
| `dark%` (L<110) | 1%~25% | `0%` = 一个字没画上；`>60%` = 整片黑 |

> ⚠️ `shot-health.py` 依赖 numpy/Pillow，**必须用系统 Python 3.11 跑**（托管的 3.13 没装）。
> 裸 `python` 会 `ModuleNotFoundError`，但若 stderr 走了管道外层仍显示 `exit=0`，
> 极易误判成"跑过了"—— 务必确认 stdout 有实际表格输出。

**★ 按镜号截图用 `shot-any-scene.py`**，关键参数不能改：
- `viewport 1920×1080` + `device_scale_factor=1` —— 必须与渲染器一致，几何才对得上
- 等待 **2600ms** —— 场景最长动画 delay+duration 约 2.2s，等满才拍到**终态**；
  等太短会拍到动画中途，误判成元素缺失

## 实战沉淀（2026-08-11/12 · 通道B premium v4 全链路）

本轮把「卡片/文字静止 + 画面更饱满」落地并跑通全链路，以下为必须长期保留的量化结论。

### A. 动态度量化门禁（`_measure_dyn2.py`）

- **采样**：成片逐镜抽帧 `fps=5,scale=320:180`，转灰度，按 2×2 步进采样像素。
- **指标**：相邻帧对逐像素 `|Δ|`；`moveFrac = |Δ|>6 的采样像素占比`。
  `lively = moveFrac>1% 的帧对占比`；`frozen = moveFrac<0.3% 的帧对占比`。
- **判据**：`lively ≥ 0.6` 且 `frozen ≤ 0.2`，任一不过即 FAIL。
- **为什么卡片静止后会击穿门禁**：原来靠卡片 float/pulse 撑起 lively；按铁律 23
  静止化后，若镜内没有卡片级微动元素，lively 会掉到 0.2 以下。
  **正确解法 = 按铁律 23 给每镜补卡片内微动元素**（图表线条流动、数据滚动、
  图标呼吸、进度条、扫描线等），幅度要足以在 320×180 降采样下仍让 >1% 像素变化；
  **错误解法 = 全屏亮度呼吸/暗角 vignette**（铁律 24 已禁，肉眼可见"背景在闪"）。

### B. headless 渲染捕获的可靠性（铁律 25 的实证细节）

| 方案 | 实测结论 |
|---|---|
| `feTurbulence` SVG 噪声数据 URI 做背景 | headless Edge **完全不渲染**，帧均亮度逐帧恒平 |
| `::after` 伪元素 + opacity 三角脉冲 | 能被 `getAnimations()` 捕获，但 5fps 采样与周期对齐 → 相邻帧对交替"大差/零差"，frozen 偏高 |
| 真实 DOM 元素 + 纯 CSS（位移/透明度/描边偏移） | 稳定捕获，lively/frozen 可预期 |

### C. OpenClaw 上传 504 体积坑

- `create_openclaw_creative_material` 内联 `dataBase64`：文件 **>~53MB（base64 >~71MB）
  稳定触发网关 504**（对照实验 0.01MB 秒过 → 纯体积超限，非服务端故障）。
- **处置**：成片先压交付版再传——`libx264 -b:v 900k -maxrate 1400k -bufsize 2800k`
  + 音频 128k，233s/1080p 约 28MB（base64 ~38MB）可过；原画质本地归档
  `final_premium_v4_full.mp4`。上传前先验文件体积，超限先重编码，不做无谓重试。
- **副作用**：504 超时的请求**服务端可能已落库**，会在素材库留下"孤儿 material"
  （无 video work 引用）。清理法：`get_openclaw_creative_materials{workspaceScope:"douyin"}`
  列出 → 对照现存 video work 的 videoUrl 提取被引用 uuid → 无引用的用
  `delete_openclaw_creative_material{materialId}` 删除。
  注意：该列表接口返回**陈旧缓存**，删除工具报「不存在或已删除」即视为已清。

### D. 本轮验证过的链路数据（可作回归基线）

59 镜全量重渲 12m24s；全镜 `_measure_dyn2` 59/59 合格（lively 0.79~1.00、
frozen 0.00~0.06）；`verify_b_08-11.py` 六步硬检查全 PASS
（动态性最小均值 6.65、段边界 Δ=0.005s、流完整 v+a）。

| 症状 | 原因 | 处置 |
|---|---|---|
| 成品字幕比参考大好几倍 | 忘了参考是 720p，直接把原生 px 用在 1080p | 全表乘 scale，并在 DESIGN.md 记录换算铁律 |

| **★ 给 `.b-pad` 加 `overflow:hidden` 后底衬消失** | 文字补底依赖 `box-shadow` **外扩**，被裁掉 | 改用「收起装饰层」从源头解决溢出 |
| **★ 半透明配角元素在暗视频上透穿** | 靠 opacity 表达"不抢戏" | 「淡而不透」：墨色抬实 + 字重降低 + 字号略收 |
| **★ 探针指标恒定不变（如恒 45%）** | 指标本身有数学缺陷，测不出声称要测的东西 | 先质疑指标：线性合成下 `keep ≡ 1-alpha`；改用达成率判据 |
| **★ 门禁脚本前台跑零输出且 exit=0** | 脚本重定向了 `sys.stdout` 到 `.log` | `python x.py; echo exit=$?; tail -30 x.log`；先 grep 确认属于哪类 |
| **★ 批量探针报的告警单跑复现不了** | 批量与单跑抓帧时刻不同，动画时序抖动 | 用单镜 `--base` 双模对照复核，判据是 LOW 数的**增量** |
| **★ 用 Read 看大 PNG 判断"有噪点"** | 大图被缩放，目视通道本身不可信 | 用 `shot-health.py` 的 `mean/std/dark%` 三条像素统计判据 |
| **★ numpy 脚本报 ModuleNotFound 但 exit=0** | stderr 走管道被吞，只有托管 3.13 没装 numpy | 用系统 Python 3.11 跑；确认 stdout 有实际表格输出 |
| **★ 截图里元素"缺失"** | 等待时间短于动画 delay+duration，拍到中途 | 截图等 2600ms 拍终态 |
| **★ 重渲染时旧文件被 SKIP 跳过** | 渲染器见文件存在就跳过 | 用自带 `--force`；沙箱禁删文件，要避让就 `shutil.move` |

| Windows ffmpeg 拼图失败 | 构建不支持 `-pattern_type glob`，`%*` 也不是合法序列 | 用连续数字序列 `%02d` 或 `xstack` 显式多路输入 |
