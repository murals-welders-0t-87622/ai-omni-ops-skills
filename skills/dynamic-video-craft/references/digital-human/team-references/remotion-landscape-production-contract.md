# 横屏 Remotion 数字人口播生产契约

> 适用 Skill：`douyin-dh-landscape-remotion-video`  
> 适用链路：策略 → 选题 → 创作 → 数字人视频专家 → 本 Skill → 复盘。  
> 本文件是该 Skill 的上游输入、配置闸口、生产工程与验收回流的唯一真源。

## 一、制作方案阶段的选用条件

视频专家仅在 `production_plan` 阶段、依据完整输入和当前可用能力评估；仅在同时满足下列条件时将本 Skill 选为主 Skill：

1. 已确认是**数字人口播型**，而非剧情、品牌广告、科普纯图解或创意吸睛型；
2. 成片为横屏 `1920×1080`；
3. 主题需要证据截图、界面巡游、数据 / 图表或多层信息表达；
4. 质量优先级高于日更速度，值得使用 Remotion 的动态 B-roll、相机与转场系统；
5. 用户接受“先出配置三件套并确认、再生产”的节奏。

单概念、速度优先的横屏口播走 `douyin-dh-landscape-html-video`；竖屏教程、案例拆解和高密度干货走 `douyin-dh-vertical-abroll-video`。用户明确选择优先于默认路由。

## 二、输入契约：创作层 → 数字人视频专家

进入配置阶段前，必须已有且已确认：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| 已确认选题 | 是 | 标题、目标指标、目标受众、内容家族 |
| 已选定生产路由 | 是 | `douyin-digital-human-video-expert` + 本 Skill ID；记录选择理由与版本 |
| 口播创作包 | 是 | 逐段口播稿、核心论点、Hook、结论、风格与结构约束 |
| 证据 / B-roll 规划 | 是 | 每段要证明什么、优先素材类型、可追溯来源或待补素材 |
| 资产清单 | 是 | 已有产品图、界面图、数据图、品牌素材；未知项必须标“待补” |
| 任务目录 | 是 | 本次产物落盘的绝对路径 |
| 合规与禁区 | 是 | 不可编造的事实、不可使用的素材或表达 |
| 策略优化记录 | 强烈建议 | 本次应继承和应避免的已验证经验 |

缺少已确认选题、本 Skill 已被视频专家选为主 Skill 的记录、口播创作包、证据规划或任务目录时，必须退回 `production_plan` 补齐或重新评估；不得用通用模板补造。

## 三、阶段 A：配置三件套（尚未生产）

数字人视频专家将上述输入交给本 Skill 后，**先生成而非要求上游提供**：

```text
<任务目录>/
├── DESIGN.md
├── STORYBOARD.md
└── demo.html
```

三份文件必须共享同一版本号、选题 ID 和镜头编号。

### 1. `DESIGN.md`

除团队统一配置规范外，必须额外明确：画幅与安全区、视觉 token、主持人固定方位、人脸安全区、字幕区、A-roll 三种形态（贴边 / 缩位 / 隐藏）、B-roll 主区、配方卡、全局 motion system 与禁用项。

### 2. `STORYBOARD.md`

每个语义段落必须写：时间范围、对应口播原文、A/B 主次、数字人形态、证据目标、素材模式、卡 / 系统、转场、字幕与音效提示。不得按“一句一个新元素”机械拆镜。

### 3. `demo.html`

必须可打开预览，并展示至少一次贴边主持、缩位让台、B-roll 主导、证据 / 图表 / 长页卡、镜头承接。它验证的是三件套的一致性，不是最终成片的替代物。

## 四、配置确认闸

配置完成后只能报告状态为 `待确认`。主理人必须向用户确认：

1. 选题与叙事结构；
2. 视觉风格与主持人位置；
3. A-roll / B-roll 主次和关键证据；
4. `demo.html` 是否通过；
5. 是否允许进入 TTS、数字人、素材、Remotion 制作。

未获得明确确认或既有自动化授权前，禁止生成或采购生产素材，禁止渲染成片，禁止将状态称为“已执行”。

## 五、阶段 B：确认后的生产输入

确认后，生产前还必须补齐：

| 字段 | 必填 | 通过标准 |
| --- | --- | --- |
| 最终口播稿 | 是 | 与配音逐字一致；数字使用中文读法 |
| 完整配音文件 | 是 | 单一 wav / mp3，无爆音、截断或误读 |
| 数字人 A-roll 素材 | 是 | 可使用的透明背景或可抠像视频；可测人脸 bbox |
| B-roll / 证据素材 | 是 | 本地落盘、可追溯；关键事实有来源截图 |
| 字级时间戳 | 是 | `timestamps.json`；句级匹配低于 0.90 必须人工听核 |
| 工程状态 | 是 | 可解析的 Remotion 工程、Composition 与渲染命令已验证 |

时间戳必须使用本 Skill 本地脚本完成：先运行 `scripts/timestamps_cpu.py`，再运行 `scripts/make_timing.py`；`timing.json` 是字幕、动效、SHOTBOOK 锚点的唯一时间来源。配音 / 数字人生成不属于本 Skill 本体；它只消费已确认的生产素材。

## 六、Remotion 工程契约

在任务目录创建独立工程，至少包含：

```text
<任务目录>/remotion/
├── package.json
├── src/
│   ├── entry.ts
│   ├── Root.tsx
│   ├── composition.tsx
│   ├── shots.ts
│   ├── timing.json
│   └── sfx.ts
├── public/
│   ├── aroll/
│   ├── broll/
│   ├── evidence/
│   └── sfx/
└── out/
```

将本 Skill 的 `template/cards/` 与 `template/motion-systems/` 作为可复制母本；按 `STORYBOARD.md` 选择性引入，不得把 78 张卡全部塞进单条视频。开始场景制作前先实现 CameraRig、视差、生命周期 / 让位和环境系统；每个边界必须有明确的运动承接或轻量转场。

工程就绪的最低证明：可列出 Composition、可加载本地素材、可成功执行一次低分辨率预览渲染。做不到时报告阻断原因和替代方案，等待用户裁决。

## 七、验收与交付契约

### 必跑验收

1. `scripts/motion_check.py`：不得存在 `≥0.8s` 的非设计性静止段；
2. `scripts/sfx_check.py`：使用 SFX 单轨确认 cue 文件和音量有效；
3. `scripts/qa_extract.py`：每句 2 帧、每个动效锚点帧、关键段连续 3 帧；
4. 独立审查：按可读性、构图、信息传达、质感、事实一致性给出 P0 / P1 / P2；
5. 手机宽度复看：缩至约 390px，确认字幕与关键文字可读；
6. 人脸安全区、A/B 让位、来源证据、字幕与最终口播稿逐项核验。

P0、P1、静止检测失败或关键事实不能追溯时，不得交付最终成片；修复后必须重新渲染和复验。

### 回传给主理人与复盘层

视频层必须回传：实际 Skill、配置版本、成片路径、验收结论、使用的 A/B 形态、主要卡 / 素材模式、异常与降级、归档状态，以及供周度复盘使用的“视频形式反馈”。
