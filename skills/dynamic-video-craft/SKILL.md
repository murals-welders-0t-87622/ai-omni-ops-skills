# 动态视频导演

需要Remotion精确时间、Canvas/Three.js混合镜头、数据与声音统一或Windows性能排错时，先读 [Remotion与混合制作](references/remotion-and-hybrid.md)。技术选择服务现有脚本/品牌目标，不改变用户已指定的引擎、终点和授权。

把素材组织成有镜头、节奏和声音的动态视频。默认使用本技能的原创 Remotion 工程骨架；镜头词汇参考 video-shotcraft 与 video-talkcraft。它是独立的中文制作入口，不要求先安装这两个上游技能。

## 先确定制作路线

从用户已给信息直接选择；缺省项说明后继续，只有主题、必需素材或关键事实无法确定时才询问。

| 输入 / 意图 | 路线 | 按需阅读 |
|---|---|---|
| 产品网址、软件截图、功能介绍、品牌宣传 | 产品片：实物或真实页面为视觉主体，按功能安排镜头 | [产品片](references/product-video.md) |
| 解说文案、成品配音、科普或知识讲解 | 解说片：先锁定讲述与时间锚点，再安排视觉响应 | [解说片](references/narrated-video.md) |
| 画廊卡名、样式名、某个具体动效 | 单镜头：精确定位卡、变体、样片与实现 | [镜头库](references/recipe-library.md) |
| 一支同时有产品演示与旁白的视频 | 以解说时间轴为骨架，为功能段选产品镜头 | 两条路线相关部分 |

用户点名 Ink Press 才走该模板；点名某张卡就保留卡约束。用户选择其他渲染引擎时服从其选择，迁移运动设计并说明与原参考实现的差异，不强制更换框架。

一般请求自主推进；只有用户要求共同设计、先看方案或分阶段确认时才设置创意确认点。上游文档中作者历史项目的偏好、推广邀请、固定审片轮数不自动成为本用户的要求。

缺省值：中文，1920×1080、30 fps。明确面向抖音、视频号竖屏、小红书竖屏或 Shorts 时用 1080×1920；其余以用户指定为准。未定时长时产品片先规划约 30–60 秒，解说片服从真实配音长度，单镜头约 4–8 秒。这些都是可调整起点。

## 制作流程

1. **看懂内容。** 读取来源，提炼观众、目标、主要信息和可用素材。对时效性事实查证来源，不编造销量、节省比例、客户评价。已有脚本优先保留；朗读稿与画面上的数字格式可以不同。
2. **定视觉。** 有产品时从真实页面提取字体、强调色、圆角和信息密度；无品牌时选一套统一视觉。先做代表性关键帧或很短的运动试样，避免整片做完才发现方向不对。
3. **定时间。** 有配音先测时长、对齐关键词；有指定音乐且以节拍为主先分析拍点。画面、字幕、转场、音效共用一份时间轴。模板的数据格式见 [工程与时间轴](references/engineering.md)。
4. **写镜头表。** 每镜记录意图、起止时间、主视觉、素材、主动作、相机、字幕、转场、声音、参考卡与变体。复杂解说镜头再写逐语义拍的主体接力，不把每一句自动切成新画面。
5. **实现。** 用模板初始化独立的视频目录，素材下载至 `public/`。按所选路线制作，修改目标是表达本片内容；模板的演示文案、数字和场景不能原封不动充当用户成片。
6. **检查与渲染。** 先运行时间轴检查和 TypeScript 编译；查看入场、信息落定、转场两侧的关键帧，再渲染和播放短运动段。确认后输出全片；针对实际缺陷修改并复查受影响部分。
7. **交付。** 给出 MP4、工程目录、镜头表、素材来源和实际验证结果。有旁白时附 SRT；带音乐时可从同一工程提供无音乐版，保留旁白与音效。用户仅要单镜头或工程时按该范围交付。

## 镜头设计的重点

- 一个语义拍突出一个对象：旧主体退场、缩为上下文，或由相机离开后再交给下一主体。同屏通常控制在 1–3 个信息组，长字幕不能另抄成整段画面文字。
- 分清背景空间、内容主体与屏幕文字。推拉、视差、揭示和焦点变化服务于信息；字幕保持稳定，不随页面相机漂移。截图上的框线则跟着截图的内容坐标移动。
- 每个主动作有准备、执行、落定和可读停留。Logo、关键数字、结论给足阅读时间；不要为了“反 PPT”而给所有东西持续抖动。数据的变化、实拍运动、轻微相机移动都可以维持画面活性；有意静止可保留。
- 转场由语义和前后镜的方向决定：推入细节、平移进入下一步、沿线条延续、形状遮挡或有意的硬切。不要在每个边界叠加多种特效。
- 模仿真实产品页面用实际截图或录屏，示意 UI 明确为示意。信息框与标注按实测坐标定位，检查放大后的清晰度。
- 精确复刻卡片时先看动态样片、读对应卡与实现，记录保留的运动结构和改变的视觉部分。只看卡名重写不能声称精确复刻。

## 工程起步

将 `<SKILL_DIR>` 替换为本文件所在目录。脚本只需 Python 3 标准库；渲染项目另需 Node.js/npm，视频检查需 FFmpeg。

```text
python "<SKILL_DIR>/scripts/init_project.py" "<项目路径>/video" --aspect landscape
python "<SKILL_DIR>/scripts/recipe_catalog.py" --library shotcraft --query deck
python "<SKILL_DIR>/scripts/check_timeline.py" "<项目路径>/video/src/video.json"
```

在新工程目录运行：

```text
npm install
npm run typecheck
npm run studio
npm run still -- out/keyframe.png --frame=65
npm run render
```

初始化参数 `--aspect portrait` 生成竖屏配置。模板含动态标题、数字、步骤和真实图片场景、相机、遮挡转场、字幕、旁白/BGM/SFX 声轨；它是工程骨架，不包含上游卡片实现。特殊镜头在此基础上编写。

## 验收与边界

用 [验收方法](references/quality.md) 核对可读性、时序、音画关系与真实成片。机器检查发现候选问题，不能替代观看；未实际试听不得声称声音已人工验收。缺配音时可以完成脚本、素材和静音预演，明确标为预演，不伪称已配音成片。

镜头目录是版本化的链接索引，不是已安装的完整素材库。查找与复用方式见 [镜头库](references/recipe-library.md)，来源及许可见 [来源说明](references/sources.md)。商业项目默认使用本技能自写代码与用户可用素材；直接复用 Talkcraft 工具包时遵守其非商业许可或已有商业授权，不把“公开视频”当作可任意商用素材。
