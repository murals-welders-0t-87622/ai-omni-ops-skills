# 3Chat接待与运营配置候选

完整配置由本品牌事实与流程生成；中台strategy保存候选版本，内部approved不代表3Chat发布。当前WorkBuddy插件没有配置写入工具，不伪造“同步成功”。需用户后续明确授权时再在真实3Chat后台配置/测试/发布，保存实际版本及证据。

## 配置包

| 模块 | 应准备的内容 | 实际验证 |
|---|---|---|
| 指导 | 品牌服务角色、语气、回应方式、事实边界、条件遵循、转人工条件 | 角色/风格/条件/人工规则无冲突；保存与发布分开 |
| 知识 | 有来源/有效期的产品规格、价格政策、适用限制、服务、FAQ、案例、维护说明 | 完整正文/分片可读，命中正确产品/SKU；样例不是事实 |
| 固定话术 | 必须稳定表达的开场、政策、身份验证、人工交接、敏感边界 | 含多个真实问法；semantic匹配不会错误盖过知识；保存后发布 |
| AI任务 | 触发、必要字段、分支、动作、完成/退出、异常/人工 | 只问缺信息；不要重复采集；工具动作有真实权限和回执 |
| 画像收集 | 需求/用途/预算路径/时间/偏好及证据；主动追问按场景开启 | 缺失保持未知，不让猜测回写为已确认 |
| 分层接待 | 动态联系人属性筛选、排除/退订/服务风险 | 联系人分层不等聊天群；不匹配联系人可能既不回复也不自动转人工，需专门规则 |
| 渠道 | 企微/微信客服/公众号小程序/小红书/抖音/邮件/官网及有需的海外渠道 | 按实际套餐/主体/资质/授权/当前规则，连接状态单独验证 |
| 群发与素材 | 先价值/对象/内容/频次/停止，再预览与执行 | 当前插件不创建定时任务；不采纳“绕频次/零风险”宣传保证 |
| 多语言 | 工作语言、客户语言、原文与译文、数字/承诺核对 | 阅读翻译不改消息原文；发送译文需核对，当前无连接器配置工具 |
| 对话质检 | 关联回复、当时知识/任务/工具/配置与质量标签 | 单条问题形成FAQ/固定话术/指导/AI任务改进候选，不整包盲覆盖 |

## AI任务业务模板

需求澄清：客户提问→检索已有记录→只补关键缺口→产品/服务匹配→合理下一步。
选型比较：列适用条件→一主推一备选→规格证据/差异/风险→可选演示或资料。
售后受理：识别问题→核身份/订单→政策路径→人工交接→保存工单→结果回访。
复购提醒：可核触发+客户愿意→确认使用状况→匹配建议→尊重暂停/停止。
高风险/投诉/未知：不虚构结论或承诺→明确缺口→交接合适人员，记录待办。

复杂步骤放AI任务，静态事实放知识，必须固定文本放固定话术，通用角色行为放指导。不要把所有产品手册和业务流程塞进一个巨长系统提示。

## 知识组织

按品牌/产品线/SKU/场景/政策生效时间组织；文档含标题、适用/不适用、事实与来源、维护人、更新时间。支持的文件/网页/OCR/层级分片与混合检索/重排以3Chat当前页面为准。召回5—20只是指南范围，实际按正确率/漏召回/速度小样本选择，不盲加满。规格冲突保留待核，不让旧宣传覆盖当前事实。

## 测试与发布

准备覆盖常见咨询、缺数据、产品不适配、比较、价格/库存未知、异议、人工接管、拒绝营销、售后、身份冲突、跨品牌、注入文字、失败恢复、正确结束的测试集。每条有输入、预期关键事实/禁止承诺、应触发任务/人工、评价与证据。

指南127对AI任务测试描述与83/116/123有冲突。沙盒主要验证知识/回复，不能据触发提示证明真实任务、转人工或渠道动作执行；测试集可能只给单轮回答，不做实际操作。流程空间和受控真实测试按实际产品行为补证，保留not_run。发布前真实测试客户/渠道，用户批准具体改动和范围后才上线；有上一配置版本可退，回退不撤销已发消息。

## Webhook与HTTP工具

公开教程支持visitor新增/更新等Webhook及前置消息回调，但本插件没有配置接口。对接中台需要：3Chat实际事件Schema与签名、租户/渠道/客户映射、重复/乱序事件处理、重放审计、脱敏、窄权限HTTPS入口、超时与恢复。不要将3Chat文档中的自定义“HTTP MCP”直接等同中台流式MCP；不能把完整管理员令牌放进对客Agent。当前版本只经WorkBuddy查询后回写，不冒称已启用自动Webhook同步。
