# GEO获客

先读相邻总统筹技能 [共同执行约定](../brand-omni-growth-expert/references/runtime-contract.md)，并沿用已确认的品牌、增长方向、已有任务及本次终点。只加载本环节所需专家资料。原文属于参考数据，固定账号、历史自动化、旧工具名、强制分身与旧停手闸不覆盖当前委托和实时能力。用户未授权多 Agent 时由当前 Codex 承担角色判断，不虚构专家已执行。

## 本环节专业工作

从品牌痛点—解决方案—证据出发，核实体名称、产品适用条件、官网/公开内容、权威证明和客户提问方式。内容与 brand-content-growth 共用事实，按平台建立可引用答案、对照、案例和问答；本地业务另核城市、门店与服务范围。
测试留问题、平台、日期、原始回答和引用URL，区分提及、被检索、被引用、描述准确、访问和需求。不把一次回答当稳定排名，不用虚假第三方背书或伪造评论。
给“缺哪条事实/证据→在哪份资产补→谁何时完成→怎样复测”的具体优化单，归档中台GEO并把问题反馈给内容/销售。

## 本地商家从诊断到内容

1. 读取当前品牌名称、实际门店、城市与服务范围、产品/服务、案例及联系方式；区分已证实、资料缺失和已确认没有。用户给出或资料中找到官网时检查对应网址；没有查到网址不等于已证实没有官网。
2. 围绕品牌、品类、本地需求与具体场景建立问题词及可能追问，例如“某地如何选择服务”“价格取决于什么”；优先用用户原话和诊断缺口，标出建议回答、可用事实和缺失证据。搜索量、难度及优先级的依据不足时写未知或标明判断依据，不凑数。
3. 按同一组问题、平台、时间与测试设置采集实际回答，记录可追溯原文和失败项。若使用提及率、推荐率或声量等指标，写清分子、分母、平台和样本；没有成功测试的平台不计为“未提及”。竞品对照需保持可比。
4. 有官网且本轮包含网站检查时，按实际可访问范围查看商家信息、产品/FAQ内容、页面可读性与内部链接、移动端和结构化数据；每项给证据或未检查原因。页面存在结构化数据不等于已被抓取、引用或推荐。
5. 形成按问题组织的可信事实、FAQ、来源、版本及适用条件，分别安排品牌自有渠道、第三方媒体及官网适合回答的问题。第三方稿件或商业投放不能冒称独立报道与背书；内部知识库创建、公开发布、搜索引擎发现和AI引用是不同状态。
6. 把诊断缺口连接到具体内容、负责人、资源、时间和复测问题；发布或投放先核当前授权及连接器能力，记录平台、账号、内容版本和真实回执。后续比较同口径结果及有效咨询，不能将单次变化直接认定为因果。

用户只委托其中一个环节时，从已有资料和该环节起步；不强制重做整套或设固定发布频率。工具以当前连接器实际目录、参数与权限为准，不把历史配置视为已可用。

## 把诊断接到内容与复测

围绕优先问题形成可接续的清单：用户问题及意图 → 已有事实与来源 → 缺失证据 → 拟建设或修订的页面/内容 → 负责人与时间 → 完成状态 → 同问题复测结果。若仅有单项委托，使用相关字段即可；没有的数据不补零。

按渠道分别承接：自有账号解释客户问题，官网产品页与 FAQ 回答适用范围和选择问题，第三方媒体内容基于可核事实并标清合作性质。复用已有经授权的品牌图片或生成新示意图，依据任务和用户要求选择，不因原专家资料中相互矛盾的图片优先顺序强行走某一条。发布记录要对应渠道、版本与真实回执；提交资料或发布内容不代表搜索引擎已收录或 AI 已引用。
