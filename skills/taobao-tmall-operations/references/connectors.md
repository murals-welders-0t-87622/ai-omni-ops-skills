# 千问办公与来源边界

千问办公里的淘宝天猫商家端连接器与WorkBuddy技能是不同能力。WorkBuddy没找到某连接器本地文件，不代表千问环境无此连接。连接器用于取数，Skill用于方法/编排，两者不能互称。

本轮原生千问识别到 `taobao-open-platform`，上报59工具及生意参谋、万相台、直播等域；59及具体范围属本次发现快照，实际执行先用客户端工具搜索/详情能力发现当前schema，不把历史数量硬编码。

推荐取证顺序：

1. 当前店铺/商家身份工具：店铺唯一ID、名称、淘宝/天猫、授权返回上下文；不要返回Token或索要密码。
2. 离线经营总览与趋势：当前周期/对照周期，用原始字段校验逐日与汇总；按接口实际去重口径解释。
3. 渠道与商品榜：同周期、粒度，保存分页完整性；商品ID不是SKU。
4. 广告账户和必要的计划/关键词/人群/商品等报表：归因窗/直接间接/单位/回溯更新时间。
5. 会员、客服、库存、退款原因：发现工具后再说可取；无接口、无权限、延迟统计不同。

2026-10-25千问上报的缺口：无会员CRM、库存、SKU明细工具；客服只有绩效汇总部分指标、无会话明细；某实时渠道树自述固定测试店铺，应排除，优先查真实授权的离线渠道工具。以上都需在当前环境复核，不视为永久平台限制。

工具界面展开的schema和回执优于模型总结。至少检查身份和支持核心判断的主要回执；记录工具名称、精确周期、关键字段、单位和错误。客户端隐藏Skill源码时明确不可读，不能假称研究过内部提示词。

缺数据时使用用户明确授权的聚合导出，或给待核验计划。千问报告中的客户身份与中台品牌映射仍须核实；不要把店铺授权自动当品牌管理员批准。

官方帮助：https://qwenwork.cn/docs/features/connectors 。连接器配置与用户在浏览器登录天猫是不同会话；本任务不授权代操作认证/重新授权。出现授权页面由用户处理，其他研究和离线计划继续。
