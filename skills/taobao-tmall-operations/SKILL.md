# 淘宝 / 天猫全流程运营

用户说“帮我看看这个店怎么运营”，先识别品牌、店铺、当前经营问题和统计周期，主动从已有资料与连接器补上下文，不把技术参数清单交给用户填写。沿用已知的店铺与目标，只询问实际影响判断而且无法取得的信息。

## 以品牌增长组织整条电商链

先读 [增长全链路](references/growth-loop.md)，从生意模式明确电商角色，再给出战略阶段/先后顺序→具体商品与运营策略→每日动作→执行证据→同口径目标实际。覆盖市场、SKU与单位经济、关键词、主图/详情/视频、自然/付费流量、活动、客服履约、会员与复盘；按 [能力覆盖](references/capability-map.md) 调现有领域方法和当前可用工具，不让用户逐个找专家。

运营问题要传到具体内容项目；评价/售后与结果回来后修相应内容或产品/履约问题。跨境方法按市场适配，当前中台没有跨境店铺适配器时，不能写成已接入或把外币记成CNY。

## 取证优先，保持经营连续

1. 核对当前中台品牌与千问办公授权店铺的对应关系。先读 [连接器取证](references/connectors.md)，确认唯一店铺标识与当前授权回执。浏览器登录成功、旧报告、工具摘要和模型自称“已连接”不能代替本轮证据。
2. 从 `manage_growth_reports` 的 `commerce_get_workspace`（`payload.commerce.area=operations`）读已有店铺、快照、计划。新店归属由品牌所有者/管理员确认后关联；不要将一个品牌的数据写进另一个品牌。
3. 最近7个完整自然日对前7日是常用起点；用户给了周期则按用户周期。读取经营、渠道、商品、推广，再核对会员/客服/库存等实际能力。数据不足仍能交付有用的待补证方案，不伪造数据或空等全部接口。
4. 按 [完整运营流程](references/workflow.md) 执行与目标相关的分析。问题导向可深入某环节，全流程策划必须覆盖全部环节及相互依赖，不按固定模板机械填数。
5. 用 [指标口径](references/metrics.md) 复算，保留事实、计算、推断、假设和待核验项。对同一SKU、流量渠道、归因与退款时间窗进行检查；不能把不同粒度混加。
6. 按 [中台契约](references/mcp.md) 保存真实来源的不可变快照，再保存完整运营方案和责任动作，回读页面 `/tabs/ecommerce/operations`。没有真实数据时标记unverified，不拿模拟值填看板。

## 分析与执行的边界

本技能可以研究、取数、计算、拟订方案、制作已获准的内容候选、写中台结果。改商品/价格/标题、报名活动、充值/调整预算/启停广告、发优惠券/短信或联系客户需要相应业务授权与当前工具能力；本技能不能凭一份策划方案自动执行。连接器含异步诉求提交不代表是只读工具，读取工具名称和schema后再决定。

内容生产调用 `ecommerce-detail-creative`：产品事实和卖点传递到详情页项目，复用当前品牌图片；不将店铺诊断里的假设变成商品宣称。发布与生成独立，店铺全流程方案不自动授权付费批量内容。

## 交付标准

给用户：一段核心判断、支持与相反证据、优先问题、分商品/渠道动作、短期与30/60/90天路线、负责人/期限/验收、资源/预算边界、缺数与验证办法。目标数字来自基线、毛利和资源推演，并标“拟议目标”，不能保证效果。

模型给出的专家意见须经复核再整合。不能把“支付=下单”“广告差额=真实亏损”“渠道UV占比=低质流量的因果证据”“ROAS>1=盈利”等错误写入最终方案。近期规则、活动机制和平台限制查官方来源，历史Skill里的标题字数或大促日期只是参考。

交付经营快照和计划版本、数据周期及证据等级；说明真正执行过的动作与只拟订的建议。保存接口成功不等于供应商调用已由平台独立证明，复盘时查真实结果与当时方案，不补造历史任务/专家执行记录。
