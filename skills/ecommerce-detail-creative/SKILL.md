# 商品详情页与创意视频

执行主体为 Codex 或 WorkBuddy。中台负责品牌资料、制作项目、版本与产物承接；不要求用户填写接口参数。用户已经提供的产品、素材、要求和批准沿用，只追问确实无法识别的业务对象或制作选择。

## 先找到正确产品

读取当前品牌身份，再读取 `manage_growth_reports` 的 `commerce_get_workspace`，`payload.commerce.area=detail`。该工作区的 `products` 是当前品牌完整产品字段，包含介绍、价格、定位、人群、痛点、场景、差异化与图片；`get_brand_products` 的清单摘要不能代替完整事实。用户只说产品简称时先匹配名称和上下文，多项确实无法区分才追问。

已有项目继续其稳定 `projectId`，比较冻结的 `productSnapshot` 和当前产品资料，说明重要变化。新项目使用 `commerce_create_detail_project` 建立，一套默认十页，按产品与用户目标可调整；不得写入其他品牌或把历史例子当商品事实。

## 按用户所需阶段交付

1. **卖点**：读 [卖点方法](references/selling-points.md)。先构建事实—特点—利益—场景—情绪价值—证据的关系，给出一句核心主张、Top3及补充卖点。完整分析保存到 `sellingPointReport`，要点保存到 `sellingPoints`，每个要点带依据。
2. **逐页文字**：读 [详情页与画面](references/page-art-direction.md)。结合产品事实和卖点，围绕吸引注意、传递价值、建立信任、帮助决策组织每页文字。没有的认证、评价、促销、服务承诺不编造，可换成有证据的产品解释/购买疑问页。先保存逐页 `copy`、`evidence`。
3. **逐页画面**：用每页文字、真实产品图、统一视觉风格生成该页 `prompt`，逐页生成并保存产物。用户指定本品牌**多元探索平台**；当前中台目录实际模型 ID 为 **`gpt-image-2`**，用户口述“gtp-image-2.0”对应此意图，执行前以实时目录校验，不新造模型别名、不改用其他平台。MCP 图像调用见 [中台读写](references/mcp.md)。逐页任务成功与失败分别记录，已成功页复用，不因一页失败重跑整套。
4. **先交付详情页，再询问视频**：“详情页已完成，是否继续制作这个产品的创意视频？” 用户已明确仅要文字/设计时到此为止。未明确继续，不调用视频生成。
5. **视频创意与制作**：读 [视频方法](references/video.md)。根据卖点与用户要求构思；无创意要求时提出能展示真实卖点的合理创新。展示创意、分镜和参数，并由用户确认**自用seedance2.0 Mini多参、480P、竖屏9:16、10秒**；允许用户调整，以应用实时能力为准。记录当前版本用户确认，执行生成、验收、回写。旧资料中的15秒不覆盖本任务10秒选择。

## 保存、恢复与验收

使用 [中台契约](references/mcp.md) 保存结果；每次读取最新 revision 后全量保存 body，保留未修改页及已有产物。版本冲突先回读并比较，不强行覆盖。产物先经已有生成/上传能力进入本品牌受控存储，再引用真实记录，不能把第三方临时链接当永久交付。

用户要改一页时只修改该页并生成新版本。视频确认仅对应当时创意、参数及版本；修改后重新确认。超时先查原供应商任务，不自动新建收费任务。

交付说明完成页数、成功图数、失败/未核验页、当前项目版本及页面入口 `/tabs/ecommerce/detail`。图片检查产品形状/颜色/Logo一致性、中文准确性、版面与卖点依据；视频实际播放检查时长/分辨率/比例、产品一致性与声画。仅返回文件地址或任务 SUCCESS 不等于画面通过。
