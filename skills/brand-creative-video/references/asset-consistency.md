# 图片资产与一致性制作

读取官方教程“一致性全面提升”以及LearnPrompt `character-reference-lock.md`、`storyboard-grid-to-video.md`的相关完整段落，再做本项目的实际图像控制。别只抄“保持一致”四个字。

## 1. 先锁定设计，再做镜头

建立风格圣经：影像路线、渲染方式、比例、主色、光源、镜头质感、人物比例、服装时代、声音风格。真实电影、拟人猫写实环境、动漫不能在同一角色上无意切换。摄影与调色服务剧情，不以“8K、史诗、顶级”代替设计。

角色母版写：脸/口鼻与眼睛、发型或毛色纹理、年龄/体型/比例、服装每一件、鞋帽饰物、姿态习惯、身份锚点、声线。产出正面、三分之四、侧面或背面等实际需要的图片；表情和说话姿态按镜头需要补充，不必每个角色固定做十张。

场景母版写空间关系、出入口、尺度、主光方向、固定物件与时间。道具母版写形状、材质、尺寸、使用状态、持握方向。品牌使用用户实际logo/字标，不让模型重新拼一个近似字样。精确文字、电话和工牌优先在后期合成，避免生成错误。

## 2. 资产登记

每一张图有稳定`asset_id`和`revision`，记录文件路径、SHA256、来源/使用范围、母版关系、继承项、排除项、是否已视觉审核。图像提示词不是图像文件：没有图就保持`planned`，不得填假hash或标`approved`。

角色参考只锁身份和衣着时，明确不继承白底、原姿势、原机位与原光线。场景参考可以控制布局但不抢走人物身份。镜头首帧负责当前构图与姿态，不能拿人物四视图直接当所有镜头首帧。

## 3. 做逐镜首帧

每镜确定角色数量与位置、视线、景别、运动起点、手与物的接触、进出方向。用已审母版生成/合成首帧，检查是否真的继承了母版。需要大转头或遮挡后再出现的镜头，补相应角度参考，别只让视频从零猜脸。

单图视频入口收到的是最终首帧。若角色母版、场景图、道具图共有多张，应先通过支持这些参考的图像工具得到一张镜头构图，再把它交给视频入口。不要把多角色拼图、四宫格、带编号分镜页和单帧构图混成一张不说明用途的输入；否则模型可能把整张网格当场景拍出来。

若用分镜网格控制多镜头，先确认所选入口确实支持此用法，并标清格序、时长和哪些文字不应进入视频。单图Mini入口优先每个生成片段一张构图明确的首帧，不强行让多格网格承担跨地点换场。

## 4. 多图槽位映射

保存`slot → asset_id@revision → local file → hash → 实际上传引用 → 控制范围`。任何`@图片N`或`Image1`都必须和真实上传顺序对应，不能出现有字无图。换入口时重新建立映射，不假设引用语法跨平台通用。

需要尾帧时也登记它的来源与版本。上一段最后可用帧用于下一段前，先检查脸、服饰、空间、手和道具是否正确；坏尾帧会把错误继承下去。

## 5. 分身镜头的特殊规则

《一只猫，四份工》：主阿橘＋订票/酒店/接车三个分身＝四只同款橘猫，白猫伴侣是另一角色。工牌只区分岗位，不改变脸、毛纹、体型。不是再创造三个随机猫品种。

按镜头登记`expected_instances`和每个实例的屏幕位置/动作/说话者。出场按明确事件发生；退场与完成的工作对应。其他镜头禁止无意多出分身，而分身镜头不能沿用“全程只有一只动物”的宠物模板。

## 6. 审核与局部返修

先审核母版，再审核首帧，再审核动起来后的身份。检查表包含：身份/服装/数量/场景/道具/文字/空间与手部关系。记录具体图片或时间码及实际观察，不能由文件存在自动判合格。

首帧错了先修首帧；首帧正确但中段漂脸才调整视频动作、角度或镜头长度。资产换版会标记下游待复核，不删除已完成素材；只重做真正受影响的片段。跨镜头不是每镜“重新设计一个差不多的人”。
