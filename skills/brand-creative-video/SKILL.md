# 品牌创意视频生成

本公开版携带本仓通用导演、项目、资产、提示词与生成/剪辑方法及公开来源导航；私有项目/第三方原文未随仓再分发。先按library-routing读取，拿到原源前不声称已核读原教程/原片。纯代码或混合镜头可经creative-production-router衔接dynamic-video-craft，复用现有脚本、项目、镜头与归档；图生视频部分仍按真实图片资产绑定，代码段不伪造生成作业。

交付一个能接续、能修订、能核验的制作工程。品牌的解决方法应改变故事结果，观众先看懂故事，再记住品牌。创意和制作方法服从当前委托，不把示例出行品牌样例的猫咪、古装、28秒或供应商固化到所有品牌。

## 开始与续做

先判断用户要的是研究、脚本、制作包、完整成片，还是修改某一阶段。沿用已确认的品牌、脚本与执行授权；仅补问真正缺失且影响工作的事项。用户说“先看脚本”时停在脚本交付；说“按这版做完整成片”时，在其已授权服务及费用范围内连续完成资产、镜头、剪辑、验收，不逐镜重复索要相同批准。

已有目录先读 `project.json`、`state/checkpoint.json` 和 `runs/events.jsonl`，保留项目及镜头ID，不重放外部提交。新项目用：

```text
python <本技能绝对路径>/scripts/project.py init --root <新项目绝对目录> --brand <品牌> --title <项目名> --max-seconds 30
```

虚构方块/圆球工程夹具：加 `--example demo-two`。它只测试两组8秒镜头及依赖，不是品牌运营案例或已生成素材。工程规范见 [项目工程](references/project-engineering.md)。

## 按阶段读资料、做产物

先读 [资料路由与来源覆盖](references/library-routing.md)，再只加载当前阶段所需的原文小节。本公开包的方法索引在 `references/document-index.json`；原始外部资料需从授权来源另行取得，不能假称已缓存或已读。不要把摘要当原文，也不要一口气加载全部资料。

| 剧本 | 同上，并查案例库 | 角色欲望、阻碍、因果升级、服务促成的反转、可见证明、自然品牌收尾；正常对白能在时长内完成 |
| 建项目与拆镜 | [项目工程](references/project-engineering.md) | 叙事镜头、生成片段与剪辑段分开；为角色/场景/道具/镜头分配稳定ID、版本和依赖 |
| 资产与首帧 | [一致性制作](references/asset-consistency.md) | 人物、服装、场景、道具、品牌资产的图片母版；逐镜首帧与参考图绑定；图片未生成时如实标待做 |
| 镜头提示词 | [提示词导演方法](references/prompt-directing.md) | 每片段有参考图映射、入场状态、可见动作、镜头、时序、出场状态、声音及不继承项 |

## 图像优先的一致性路径

本技能的品牌创意制作以图像资产驱动视频。先建立角色/场景/道具图片，再制成镜头首帧；不能只在文字里说“长得一样”。

- 多参考图入口：按实际上传顺序，将稳定资产ID/版本映射到真实参考槽位，再写该入口支持的引用语法。
- 单图入口：用已审的角色、场景、道具母版合成或生成一张正确的镜头首帧，再送图生视频。不要假装给单图接口传进了多张资产图。
- 参考图、首帧、视频逐层检查；某一层变更，只标记依赖它的下游产物待复核。不要为修一个手势重做全片。

当前附带的 RunningHub 应用 `2069739201603661825` 公开暴露单图片口、4—15秒时长。它不等同于官方手册中支持多模态的完整入口。当前参数快照见 [应用能力](references/provider-profiles/runninghub-seedance-mini.json)，制作时仍需刷新实际schema。

## 执行与结果边界

用户授权创建技能，不等于授权本轮付费出图、出视频或发布。未来实际制作时，依据用户已给的供应商/素材/预算/重试范围执行；缺这些关键条件只问一次。既有授权范围内可自动校验、下载本项目输出和局部修复。未知成本不当0，来源示例额度不当预算。

工具调用优先使用用户指定并已连接的MCP；可用的本地工具和其他入口作为适配路径。每次绑定保存schema证据，不能猜工具名、节点ID或字段。只保存凭据环境变量的名称，密钥值不进工程、日志、提示词和技能包。

提交前用 `project.py validate`；可用 `project.py reserve` 在本地为外部调用留提交意图。它不是供应商提交器。实际调用成功后用 `project.py event` 保存回执。返回不明或已有待查任务时，先对账，禁止盲目补交重复付费任务。

“计划就绪”“资产已生成”“供应商成功”“画面审核通过”“成片已验收”分别报告。交付成片需真实文件、播放预览和验收记录；没有执行能力时交完整可执行制作包并说明缺口。不得把静帧拉长或重复镜头当成缺失的生成镜头。

## 本地工具

- [project.py](scripts/project.py)：新建工程、状态核对、依赖检查、提交意图、外部回执、变更失效标记。
- [library.py](scripts/library.py)：本包方法检索、按阶段定位，分段读取实际文件。
- [prepare_request.py](scripts/prepare_request.py)：用已审核首帧和实际上传引用生成单图应用请求文件；不发送请求。
- [verify_package.py](scripts/verify_package.py)：本公开包自有方法hash、链接、示例与实际索引核对。
- [离线验收](tests/test_workflow.py)：在隔离夹具中检查初始化、时轴、资产依赖、单图请求、授权/任务上限、超时与重复回执；不访问供应商。

Codex UI元数据在 `agents/openai.yaml`；WorkBuddy同样可加载标准 `SKILL.md`，宿主差异见 [兼容说明](references/host-compatibility.md)。本技能不安装或修改 LocalMiniDrama，不改正式专家团/连接器，不自行部署或发布。
