# 安装与更新 AI 全域运营系统

用户说“安装整套系统”或“更新整套系统”时，从这里开始；直接执行可做的步骤并报告，不让用户拼技术命令。本技能是安装维护入口，不替代品牌增长总统筹及业务技能。

1. 读取 [Windows Docker 安装与更新手册](references/windows-docker.md)，并确认当前目标机器、现有安装、数据和实际授权，区分新装、已有系统更新、历史迁移。仅已连接、确有写入目标和权限时操作；无法确认的数据保留原状。
2. 新装使用手册指定的公开中台仓和公开技能仓，先检查环境、端口、旧项目、凭据与磁盘。复用已克隆的技能仓；无需另克隆一份。新环境准备可直接运行 [prepare-new-machine.ps1](scripts/prepare-new-machine.ps1)，首次默认预检，只有确定空目标才运行 `-Prepare`；然后依手册 Docker 构建、启动和核验；为本次新建的独立实例按手册设置并实际验收平台管理员。已有环境不能当新环境初始化。
3. 更新时先核现有仓库、运行配置、卷和在途任务，做好一致性数据库/素材/配置备份并校验恢复路径；评估实际 schema 和发布变更，确认安全才快进更新及构建。发现丢数据风险、冲突、备份不完整或目标不明确则停止相关部分并说明，不能靠强制或重新初始化继续。
4. 调用技能仓受管安装器完成全部技能的 validate、dry-run、install、doctor；保留安装事务和用户本地修改。Codex 新对话发现与文件安装分别验证；实际品牌 MCP、外部连接和宿主 Codex 执行器分别检查，缺授权不杜撰成功。
5. 汇报仓库及 SHA、部署/卷/备份位置、版本、服务健康、登录、技能发现、MCP 和执行器的真实结果、失败恢复点。公开仓不需要仓库授权；Docker、网络、模型凭据及第三方授权仍由目标设备的实际条件决定。旧私有仓与新公开仓历史不同，不直接覆盖或强行快进，先按手册评估备份与迁移。

只使用用户指定的实例，不修改原中台、其他项目、他人凭据或未授权的外部经营；不提交秘密、发消息、执行广告或支付。更新源与需恢复的数据或密钥不明确时，先诊断可做部分并如实说明。
