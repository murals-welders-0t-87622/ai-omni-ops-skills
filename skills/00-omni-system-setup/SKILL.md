# 安装与更新 AI 全域运营系统

用户说“安装整套系统”或“更新整套系统”时，从这里开始；直接执行可做的步骤并报告，不让用户拼技术命令。本技能是安装维护入口，不替代品牌增长总统筹及业务技能。

1. 先确认本次意图：仅安装技能、接入已有中台，还是安装/更新中台；按 [双版本与客户端接入](references/deployment-and-agents.md) 只读识别目标实例、实际品牌连接和客户端，不以 Docker 缺失断定整个系统不可用。已有多实例且目标不明时先消歧，不能自行新建或切换。
2. 仅安装技能或连接已有实例时不安装、更新或重建中台。按当前客户端实际支持的目录和加载机制安装技能、保留本地修改，区分文件安装和客户端实际发现。工作区路由只在客户端实际读取的指令文件及用户实际工作区配置；Codex 可用 [工作区路由指引](scripts/configure-workspace.py)，不能假定 WorkBuddy 也读取 AGENTS.md。
3. Docker 版的安装/更新才读取 [Windows Docker 安装与更新手册](references/windows-docker.md) 并检查 Docker；仅在确认空目标的新机使用 [prepare-new-machine.ps1](scripts/prepare-new-machine.ps1)。已有 Docker 实例先核版本、在途任务和数据保护，再按手册处理。
4. 原生安装包版依实际安装包版本和官方更新入口操作，先核实例、程序和数据目录、版本、激活、运行状态；不得套用 Docker 构建、数据库初始化或直接覆盖。正式原生更新通道是否可用须现场验证，不假定研发工具等于客户一键更新。
5. 使用当前实例的品牌 MCP 配置，检查连接与实际工具列表并核对目标品牌；如果禁止裸 HTTP 检查，以 MCP 只读调用举证，别推断业务写入已通过。启动新任务或按客户端支持方式刷新技能索引后验证发现情况；验证总统筹、领域技能和跨技能接力各自报告，业务任务仅按实际授权验证。
6. 汇报实例类型、客户端、技能安装与发现、实际品牌连接及测试边界；缺失的组件、权限和需在目标电脑确认的事项分开说明，不输出令牌或密钥。

只使用用户指定的实例，不修改原中台、其他项目、他人凭据或未授权的外部经营；不提交秘密、发消息、执行广告或支付。更新源与需恢复的数据或密钥不明确时，先诊断可做部分并如实说明。
