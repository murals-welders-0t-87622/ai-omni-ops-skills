# Docker / Windows 安装包与 AI 客户端接入

## 先确定当前实例，再选择操作

| 现状 | 处理 | 不应推断 |
|---|---|---|
| 已有 Windows 安装包中台 | 查用户实际安装目录、启动器、正在使用的网页及品牌 MCP；只接入时无需 Docker。 | 找到启动器不代表服务正在运行，工具可见不代表所有业务已验收。 |
| 已有 Docker 中台 | 核对当前 Compose 项目、端口、数据卷、正在运行的服务；按 Windows Docker 手册维护。 | Docker 命令存在不代表引擎运行或这是目标实例。 |
| 两种均有、信息不足或结果矛盾 | 列出非敏感的版本/端口和观察依据；选择用户指定实例。 | 不按固定端口、目录名、测试品牌或是否装 Docker 自动决定目标。 |
| 只安装技能 | 只处理客户端技能和其支持的指令规则；无须安装、启动或更新中台。 | 技能文件安装不代表 MCP 已连接或当前会话已加载。 |

识别尽量只读：用户已有连接配置和中台实际界面优先；可用时查看启动进程或 Compose 状态。根据实际安装目录和版本核对，不扫描或输出令牌、密码与业务数据；无法读取时标记未知。不同机器可能端口不同，不把两个同端口实例当作同一套系统。

## 连接 WorkBuddy / 其他 Agent

1. 从目标实例的「接口与连接器配置 / OpenClaw 安装」按当前界面取得本品牌 MCP 配置，在客户端支持的位置配置和启用；使用实际显示的地址、令牌及品牌信息，不把凭据写进技能仓、公开文档或对话。不要直接猜测工具名或接口版本。
2. 在目标客户端确认技能的实际安装位置与完整文件、参考资料，并按该客户端支持的方式刷新索引或新建任务。当前会话缓存不更新时不能把文件存在说成已加载；不支持的技能格式或本机脚本需明确指出。26 是本次仓库登记数，实际以本仓 registry 为准。
3. 工作区指令要写入该客户端实际支持且会加载的位置；`AGENTS.md` 是 Codex 的项目指令机制，不能假定 WorkBuddy 自动读取。已有规则应保留，冲突需检查；不同工作区按客户端规则确认指令是否覆盖。若无受支持的项目指令入口，标明未配置，提供任务启动时的总统筹路由提示，不能宣称永久自动记住。
4. 新任务中做非破坏性验证：确认总统筹及目标领域技能能被发现；针对当前品牌通过 MCP 只读列工具或读取品牌资料。区分工具列表、品牌权限、真实调用及写回；未进行真实业务不得报告端到端通过。网络探测被沙箱拦截时，使用已授权客户端的 MCP 调用作为对应证据，不擅自绕过隔离。
5. 业务数据与版本变更只针对选定实例。连接失败先核地址、实例是否启动、品牌凭据及客户端授权；原生启动窗口关闭可能停止该版本服务，依实际版本验证，不一概要求重启 Docker。

## 原生版更新边界

安装包研发目录中的受管更新和测试样品不等于客户正式自动更新渠道。先核查当前发行版本提供的入口和签名；没有受信更新包或入口时说明不能自动升级，保留程序、数据与许可信息，不用 Docker 源码覆盖安装目录。数据库与在途任务保护按实际更新流程处理；需要迁移时先核对数据目录、兼容性与可恢复性。
