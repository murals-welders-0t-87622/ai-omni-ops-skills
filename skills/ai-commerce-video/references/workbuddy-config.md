# 用WorkBuddy专家配置指导创作



## 能读取什么



本机安装注册表可定位当前登记版本的installPath；包内plugin.json给单专家/专家团、入口角色与技能目录，agents/*.md给角色提示词，skills/*/SKILL.md和其references给方法、输入输出与约束。可以按用户授权读取这些配置来组织内容。没有连接器时，本地文件读取仍可用；远端/未下载且无授权接口的配置不可假装可读。



scripts/inspect_workbuddy_config.py提供只读目录发现和指定包快照，只读取专业配置文件；不导出.mcp.json、settings中的密钥/环境或认证缓存。使用`--plugin NAME --output 目标.json`定位当前安装版；`--allow-source`才允许读取市场源码，并标source_only。必要references按任务再读，不默认整库加载。



## 三种不同事实



1. 配置已读取：确认文件、版本、hash与观察范围。

2. 按配置方法生成：当前执行者读取相应输入/参考后完成，明确“由当前助手按配置生成”，不能伪称原专家到场。

3. 真正调用专家：使用宿主真实专家/团队调度，保留实际调用/回传与产物；只有提示词、文件安装或网页排队不算执行。



读团队配置不意味着自动获得其成员调用能力。团队若要求主理人建团队、专业成员执行及质检，只有宿主支持且当前用户授权时才能声称走完该流程；不能模拟成员发言或把一个人改写成多位专家验收。只借方法时，按当前用户范围执行并注明未运行原团，不把原团运营命令当新授权。



## 适配顺序



先定用户目标与对象→定位对应安装版→读角色与其必需技能/参考→提取输入要求、方法、交付及事实边界→与当前指令冲突处以当前指令及宿主规则为准→读取当前品牌真实资料→产出并标来源→按已有授权归档。未知接口以实时Schema查，不从配置中硬编码过期MCP名称或凭证。



单纯问“能不能根据配置生成”不授权后台发消息、调用收费模型、发布、增加权限或修改其他专家。一个专家专有平台工具缺失时可先输出脚本/方案和缺口，不声称已剪出视频。
