# 技能库结构与持续融入

从用户生意模式和目标出发，一条业务事实先落本品牌；通用方法才入公共技能。边界：

| 内容 | 归属 | 发布条件 |
|---|---|---|
| 原始数据、客户、实际作品、用户反馈、实验候选/用户选择 | 本品牌中台可用对象或私有工作区 | 按实际schema保存，标清回执和权限，不提交公开Git |
| 品牌与特定平台/人群/产品有效经验 | 品牌资料/已选策略/任务版本 | 记录范围、来源、样本、反例、有效期及复测，不自动升级为全局规律 |
| 跨场景可复用的判断、方法或操作 | 对应领域 `references/`，入口 `SKILL.md` 只保留触发与必要路由 | 用户选定的实验验证后；记录条件与证据，且反例、失败和不足都保存 |
| 来源、采纳/不采纳和验证状态 | `registry/learning-sources.json`；公开只存许可允许的摘要与链接 | 记录真实读取范围、版本/日期、许可；不复制未经许可原文 |
| 可执行校验或算法 | 负责领域的 `scripts/` 和 `tests/` | 面向真实失败写测试，不把模型语言检查或脚本模拟当商业结果 |
| 版本、发布、安装 | 领域版本、`registry/skills.json`、`CHANGELOG.md`、release manifest | `omni-skill-maintenance` 负责校验、备份、隔离安装与授权范围内同步 |
| 跨板块协同 | `brand-omni-growth-expert`、`omni-growth-review` 负责统一业务目标和结果 | 不强迫所有任务走完整流程；变更主职责/框架需用户事先确认 |

在内容板块，经营数据/选题与创意判断入 `brand-content-growth`、平台步骤归 `douyin-operations` / `xiaohongshu-operations`，视觉/声音/镜头技术归 `creative-production-router` 及相应制作技能，经营结论交 `omni-growth-review`。电商/私域/销售/广告、系统可靠性同理，修改真正负责的领域，不集中堆入本技能。本技能只负责反馈→假设→用户选择→验证→沉淀的连接。

新增内容不强制每份领域文档采用统一冗长模板：将适用场景、输入及对象、操作和判断、指标口径、证据来源/限制、交接和失败恢复放入最合适的文件，入口保持短、按需加载。对现有技能先检查重复与冲突，列出修改地图、待验证项和版本，不因一篇资料覆盖有效方法；维护者核语义，不绕过架构锁。
