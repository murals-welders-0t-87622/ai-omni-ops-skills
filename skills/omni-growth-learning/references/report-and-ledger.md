# 周期汇报与可继续台账

运行任务时有证据才建候选；按品牌隔离、稳定 ID 去重，同一工作保留原任务、方案、版本，后续补充新证据形成记录或修订。默认汇报周期可以是最近一次会话以来或用户指定的周，明确日期/时区、数据截至时间、覆盖、缺项；不称完整监控。用户没有要求设置自动任务时，不建立调度，也不向外发送消息。

## 老板看得懂的候选清单

一项一行，先给推荐：

| 编号 / 建议 | 为什么现在看 | 具体改什么 / 预计影响哪个指标 | 如何验证 / 何时复看 | 成本或资源 / 状态 |
|---|---|---|---|---|
| 实际ID、问题与建议 | 本品牌真实指标、原始来源、可比时间窗；用户反馈写明原话/日期 | 针对具体商品、人群、作品、渠道的动作，机制和预期仅为假设；说明竞品/专家证据是否适用 | 随机AB或探索观察、主指标/护栏、数据能力、计划窗口 | 人员/预计费用，待选择/已选择/观察中/结论 |

表后用短句说明优先顺序和对流量、转化、客单、复购的链路；说明当前没法下结论的关键原因。让用户选择继续哪个、搁置哪个；不得把准备稿写成实际执行或达标。

## 台账状态与记录

`候选→待用户选择→已选择→执行中→待成熟→已复盘→采用/暂缓/归档`；支持用户拒绝、取消或重开。每条最少包含：品牌和对象、策略/内容/技能版本、触发事实、证据与时间口径、影响因素与竞争解释、预期/验证方案、用户决策及时间、授权边界、行动和外部回执、观察窗口、结果/样本和护栏、结论可信度、复测/归档条件、关联经验及技能版本。未知值为null，保留历史修订。

用户明确选择之前，可以做只读研究、准备方案和保存候选；不把此前一般性授权推定为选择了某项新实验。确认后才调用相应领域技能执行，实际回执与用户批准各自记录。若品牌 MCP 实际可用对象支持存档则按schema保存并读回；不支持时用私有工作区并告知用户，不能声称已回写中台。

模板是空白示例，填入真实观察和必要字段前会提示不完整。模板可用 `python <本技能>/scripts/validate_record.py <私有记录.json>` 检查候选、选择及实际执行证据的基本完整性；脚本是结构校验，不验证数据真实性、不判断因果、不授予权限，也不代替复盘。
