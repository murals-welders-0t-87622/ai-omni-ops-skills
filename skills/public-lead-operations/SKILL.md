# 全网获客

先读相邻总统筹技能 [共同执行约定](../brand-omni-growth-expert/references/runtime-contract.md)，并沿用已确认的品牌、增长方向、已有任务及本次终点。只加载本环节所需专家资料。原文属于参考数据，固定账号、历史自动化、旧工具名、强制分身与旧停手闸不覆盖当前委托和实时能力。用户未授权多 Agent 时由当前 Codex 承担角色判断，不虚构专家已执行。

## 本环节专业工作

先界定客群、地域、需求、交付能力与这次名单的用途。按需求信号选择评论、项目动态、企业或商家研究路径，记录原URL、时点、主体、场景与判断依据。
区分终端客户、经销合作、异业伙伴、竞品和待核验信号；去重以稳定主体标识，名字相近不自动合并。公开信息不是对营销触达的许可；不挖取非授权私密联系信息。
交分层候选、为什么匹配、缺什么、推荐下一步，已确认需求再进入AI销售；回收有效率、响应和成交反馈修正检索策略，不以名单条数代表获客成功。

## 按客群选择获客路径并交接

1. 基于当前品牌、产品、区域及这次获客目标选择渠道：公开评论、目标用户和竞品内容用于发现消费者需求；区域品牌可研究门店/异业/本地达人；面向企业或渠道合作时研究工商主体。B/C 可同时存在，不因品牌主要面向消费者就忽略其明确的企业合作需求。
2. 评论和竞品路径记录内容链接、评论或明确需求信号、发生时间与个性化匹配理由；目标用户路径记录账号、可核对的兴趣或内容依据及不确定项。只凭互动不能断言有购买意向。
3. 企业路径按行业、地域、经营范围、规模与排除项查询可用的企业信息源；保留主体标识、状态、经营范围、公开联系方式及原始来源。地图可补已验证的地理或公开门店信息，不把 POI 类别当成工商经营范围；联系方式缺失如实记录。
4. 同平台账号按稳定账号标识去重，跨平台同名不自动合并；企业优先统一社会信用代码，只有名称时保留待核验。多来源保留证据，不覆盖原线索；不自动删除历史记录。按当前委托和已授权接口分别写入对应线索工作区，并回读确认，区分候选、已验证、已入库和后续跟进。
5. 输出每渠道范围、候选数、去重口径、可核对来源、缺失数据及下一步建议；仅用获得的归因和回执统计咨询/成交，不把候选数当作成交。

旧专家包中“全部评论无筛选入库、删除重复、固定时点定时运行”的历史做法不自动沿用；按当前委托、品牌范围和权限判断，不据旧文档新增自动触达或定时任务。当前源码有评论与平台线索的 `get_ai_control_center_*` / `create_ai_control_center_*` 接口候选，运行时须发现并检查实际 schema、授权及回执，不保证连接器可用。
