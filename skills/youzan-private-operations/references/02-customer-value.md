# 同一客户，一人千面

## 数字化标签与生命周期（2.0）

标签应显示定义、来源、规则、人数、变化和对应动作。区分来源/渠道；交易（首购、多购、R/F/M、品类规格）；互动（浏览/加购/响应）；资产（等级/积分/券）；服务（具体未结事项）；主动需求/偏好；渠道联系选择。无对应日志不生成该维度事实，仍可给出规则及所缺字段。

交易明细可计算观察期购次、距上次购买天数、品类规格和金额，不必等待客户手动陈述这些交易事实。真实首购需完整首笔历史；生命周期阈值依据品牌/品类，低频不照搬30天流失。RFM不自动等于终身价值、适配或可联系。

同一数据版本计算标签/人群，规则变更重算且保留旧版。客户主档、来源散列统计对象、外部渠道身份分别管理，不能用统计散列直接发消息。

## 主档与身份

中台AI销售customer是客户主档，有赞/3Chat/门店身份为来源映射。稳定来源键至少包括provider、店铺/空间/渠道、客户ID。脱敏片段、姓名相似、电话尾号、占位ID不能作为合并依据。没有可靠同人证明，保留待关联来源，不创建一堆假客户，不关联到其他品牌。

购买者、使用者、监护/家庭联系人、企业采购与决策人是不同角色；关系应由可靠来源确认。订单中的护理商品不证明疾病、怀孕、年龄、家庭关系或健康状态。需要专业判断的问题转合适人员，技能不能诊断或承诺疗效。

## 标签与需求

标签定义记录：组、定义、可并存/互斥、适用范围、人工/自动规则、重算时机、证据要求、维护人。定义修改产生新版本，既有断言需复核，不能悄悄改变历史含义。

客户标签断言记录：customerId、tagId、值、场景、事实发生时间、来源类型、原话/订单/回执/人工依据、可选置信度、有效期和状态。

- confirmed：有可回溯依据，不等于绝对真实；provider_receipt仍是执行端上报。
- candidate：AI推断/未证实，不能作为确定人群或确定事实推荐。
- conflict：同一场景互斥依据并存，保留双方并提示核对。
- expired / definition_changed：已过有效期/定义更新待复核，从有效分群排除。
- revoked：已撤销，历史保留。

客户表达、行为和订单事实可按明确规则自动形成有依据标签，无需为每个普通标签额外创建审批；对健康、关系等无证据推断不能这么做。业务规则应有来源、版本和影响人群预览，不采用购买三次即忠诚等通用硬阈值。

need记录当前角色、场景、需求、偏好、目标、约束、复查时间与证据。同一人可在工作、家庭、自用、送礼、购买前、使用中、售后等场景有不同需求。旧需求不删；按时点复查，而不是永久贴一个人格标签。

## 个性化行动

每次回答：此人现在需要什么，为什么；推荐哪项服务/内容/产品，匹配依据；什么情况下不适用；下一动作和验收。

优先处理未解决工单、使用障碍和承诺。拒绝、退订、渠道偏好、频率疲劳、重复旅程、已购、已处理服务、未履约容量均应影响动作。群体策略只是候选，个体触达前再核对即时状态。

私域运营准备计划/权益/旅程；AI销售负责具体沟通、商机、跟进、服务与到账记录。3Chat发送使用其现有具体授权与发送恢复规则，accepted/processed不当送达/已读/成交。记录客户受益、响应、问题解决与不满意，不能只看GMV。
