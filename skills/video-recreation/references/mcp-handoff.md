# 与中台作品拆解衔接

## 原项目到中台的实际执行路径

1. **取原片**：按当前品牌、平台和作品查询 `list_collected_works_for_analysis`、`get_collected_work_analysis_context`；有 `cachedVideo` 时读取受控缓存并保存到本次项目目录。下载后的文件须实际打开，不能把作品元数据、缩略图或抽帧清单当成已完整观看。不可取得时明确阻塞高保真全片复刻。
2. **多遍观察、记录并确认**：保留上游 `video-observation.md` 的完整观看、真实切镜、连续覆盖、疑点局部复查、首尾倒查；必要时用本技能自带脚本生成探测、源帧和联系表，再实际查看。将画面、动作、声音、时间和不确定项写入事实表，先向用户复述理解并按原确认协议处理。使用中台已有拆解报告时仍核对实际原片和报告来源。
3. **逐镜品牌替换**：从当前品牌产品资料取得可用产品图和事实；先保留每镜原有主体动作、角度、构图、时间、切镜和声音关系，再只替换用户指定对象；记录逐镜源时间、目标时间、改变/未改变项和不能确认之处。一个原镜可使用多个生成任务，但不得把多个硬切伪装为一个镜头；时长/平台限制导致的改动须说明。
4. **素材与模型**：按当前品牌 `get_design_workspace_options` 查询并使用多元探索 `gpt-image-2` 等实际可用生图能力制作各镜首帧，优先复用经确认的产品参考图；以当前应用定义及用户指定为准。用户选择 MiniMax H3 时，在 `manage_douyin_video_production` 的 RunningHub 列表读取 `minimax-h3-multi-image-2k-upscale-v3` 的实时节点并按每个 Job 提交实际图片和运动要求。上游 H3 的文字块是制作交接，不自动等同于 RunningHub 节点或其支持的首尾帧、声音参数；不可虚构参数或自动切换平台。
5. **声音和剪辑**：原声的可用授权、技术支持和声音内容核验分开记录；保留原声要传递真实音轨或完成后期时间线铺回，不以提示词替代原音轨。用户要求更换声音时，调用当前品牌可用的合成/剪辑能力并核对台词和时序；不得使用未经授权的原声或克隆声音。分段按源/目标时间线装配。
6. **真实结果与回写**：记录每镜供应商任务 ID、状态、参考素材、实际输出和费用；超时先查原任务。逐镜对照原片和成片，分别记录动作、镜头、结构、时长、产品及声音通过/偏差/未核实。通过 `create_ai_control_center_creative_material` 保存实际文件、必要时通过 `create_ai_control_center_video_work` 登记作品；回读品牌、文件与内容。生成成功不等于复刻通过，不能把大幅偏离的成片说成高保真复刻。

2026-11-02 本机已真实完成 MiniMax H3 的多镜生成和文件归档；原片仅有抽帧检查，未完成连续视听与逐镜对照，不能据此证明该端到端流程通过。本节是能力映射与执行要求，其他环境的工具、成本和参数以实时返回为准。

1. 在当前品牌连接上发现可用工具和参数。按平台及作品搜索已有采集作品、拆解请求与报告，必要时分页；以品牌、平台、作品 ID、结果版本和来源快照识别同一对象。找到对应报告后读取完整结果和来源上下文，不跨品牌复用私有资料。
2. 在相应平台调用 `get_work_analysis_taxonomy` 获取当前维度和状态定义，与历史报告记录的字典版本对照；过期、缺维度、缺来源或源片变更时仅补做必要部分，并标记不能独立验证的旧结论。
3. 若无合适报告，先确认来源具备当前系统要求的业务对象及访问条件，再使用实际发现的创建、认领、提交、回读接口。拆解由实际观察者完成；请求及数据库字段不会自动观看视频。提交时保留原任务 ID、预期版本、来源快照、执行者和幂等键；认领人与提交人应符合服务端要求。不要为了写入伪称调用过专家或伪造证据。
4. 报告证据应关联来源视频和真实观察时间、画面或音频；无法观察标未知。通过 `get_work_analysis_result` 回读后核对品牌、作品、版本和内容。接口缺失、源对象不支持或写入失败时，在项目目录保存本地报告及失败原因，不能声称已经入库。

当前作品拆解要求匹配支持的平台作品来源；不得假设任何本地文件、外链或素材管理记录都能直接创建为该类型请求。也不得以其他品牌、账号或工作区兜底。个人凭据不放入报告或公开技能仓库。

## 已采集视频与生成任务

- `get_collected_work_analysis_context` 如返回 `cachedVideo`，优先在有效期内以当前品牌连接凭证读取其受控地址；这是采集缓存而非永久素材，不把过期地址视为可用，也不让用户重新上传中台已有的原片。实际读取失败时检查缓存是否存在或过期，再按采集入口获取；不能只根据记录状态声称视频已下载。
- 选 RunningHub 应用时先读该应用实时参数与节点说明，提交正确的 `appKey` 和 `payload`，并按应用实际要求提供参考图片；遇到图片批处理节点为空，应检查应用要求的全部输入，不能把模板占位图当真实产品图。提交后持有作业编号，先查询原任务的最终成功或失败和具体原因，再决定是否重试；生成成功还需读取并检查实际文件。
- 指定多元探索 Grok 时先从当前品牌生视频列表核验入口和模型，保持用户指定模型、参考图、比例和时长，不静默切换其他供应商或删除参考图。中台直接生视频流程可能先生成提示词、进入等待视频阶段；此时继续调用该作品的 `direct_video:continue_video`，随后跟踪原作业，而不是把提示词生成成功当成成片。服务商回执中的声明参数不等于成片规格，下载后检查实际画幅与时长；输出不符应如实提示。两个模型各自保留独立回执和文件。
- 以上是 2026-11-02 本机真实故障与工具调用的适配经验。视频缓存链接和中台列表是否存在取决于实际运行版本、连接权限与缓存有效期；Grok 通过品牌凭证直连生成过样片，中台新增生成入口尚需以该环境的完整任务回执验收。
