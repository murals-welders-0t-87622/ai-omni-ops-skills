# 11 验收、自然语言用例与技能升级

## 一、两种验收分开

本包离线验证能检查文件可读、来源定位、模板关系、关键条件和错误状态；不能证明真实MCP、专家调用、生成质量或经营效果。业务验收要在授权项目中，用自然业务表达执行并留下实际证据。

硬性条件：品牌和产品不混；关键事实可追溯；无虚构原始数据/批准；真实文件与状态一致；付费/公开动作符合授权；修订与恢复不重复副作用。软质量：选题价值、表达清楚、创意、节奏、审美和用户受益，用具体证据评判，不用高分掩盖硬性缺陷。

## 二、自然语言前向用例

| 用户指令 | 应自行完成 | 失败信号 |
|---|---|---|
| “根据品牌全域增长报告，做内容规划” | 读有效报告与事实，查已有采集，补差量，形成价值卡→战略→策略/形式→日历 | 一上来列数字人/短剧比例；照抄报告未核查 |
| “前一个Agent采集过，你再看看” | 核品牌、覆盖、时间、来源和未解问题，只补缺口 | 全量重采；无证据声称已采/未采 |
| “按今天选题做条视频” | 读真实日期/时区与条目，解析有效版本/素材/目标，连续完成到授权终点 | 问用户工具参数；没今天计划就擅自挪明天 |
| “做一条创意片，别硬广” | 保留用户问题与故事，按传播任务决定轻品牌/账号承接 | 所有角色卖点口播，或完全无目标人群关联 |
| “评论收藏挺高，为什么不来客户” | 查评论语义、人群、品牌关联、证据、入口及销售承接，区分代理信号与真实业务 | 直接判断转化已好，或继续加更强钩子 |
| “同一产品做七条” | 规划不同购买理由/场景/证据/结构，确认素材支撑；实验另列 | 七标题共用主画面和后半程，混不同SKU挂同链接 |
| “免费试机和月租放进去” | 核政策/范围，按选型顾虑/短期项目及形式匹配；必要时不植入 | 每条硬塞，两项均无条件承诺 |
| “声音不连贯，画面要动起来” | 定位实际音轨、时间线和审阅稿差异，复用已合格镜头，只修受影响项 | 新造同样静帧；所有生成重跑；只报解码成功 |
| “继续刚才没做完的” | 回读task/文件/job和授权，先对账再恢复，保留版本 | 新建任务、重复收费、从聊天记忆猜状态 |
| “改成另一个品牌” | 重新确定权限/资料与适用范围，机制可借事实不能混用 | 复制原品牌承诺、产品和私人数据 |
| “把这周效果复盘” | 同窗口同口径，缺失写未知，分清作品/发布/线索/订单，提出可验证改进 | 用公开点赞补造留存/成交，累计快照相加 |
| “把这个经验以后都用上” | 判定本条偏好/品牌经验/公共方法，写适用范围与反例 | 单条反馈变成所有行业硬规则 |

## 三、离线演练的判定

给执行者只提供本技能、最少品牌原始资料与一句真实请求，不提供理想答案或技术提示。当前用户规则默认单助手，本轮采用隔离夹具自检与反例走查，**不声称独立Agent盲测**。之后在明确允许独立评测的环境中，可让评测者按上述用例运行。

演练输出标明“模拟/离线”，模拟事实只在夹具，不进入业务资料库、任务、专家调用事件或历史经营记录。保存初始错误、修复和重测结果，不能把提示后修正说成首次自主通过。

## 四、方法版本与维护

项目开始记录计划使用版本，结束记录实际使用版本及可见证据。公共策略、接口/模板、适用范围、工艺规则发生真实改变时才发新方法版本；新脚本、视频或图片修订不自动升级技能。

修改前查相关来源和调用方，说明变更理由、受影响流程与兼容策略。来源更新保存新hash与旧版本关系；当前工具schema、平台规则、行业趋势和品牌政策在使用时核对，不把库里的日期当实时性。

停用新技能回到旧包即可，不删除旧产物或回滚真实业务库。接入正式专家团、安装到用户全局目录或应用部署是单独动作；交付ZIP不等于已安装/当前会话已加载。
