# 02 用户痛点、行业趋势与差量研究

## 1. 接上游，保留独立判断

读取品牌全域增长报告的品牌、版本、日期、采用状态、目标客群、增长瓶颈、产品服务、证据、资源与承接。报告不完整或过期，不一律重做全域报告：列出影响当前内容的差量问题，独立补查。

优先读取品牌档案、产品/SKU、服务政策、历史内容/指标、案例、当前营销计划、销售客服与交付反馈。产品说明是品牌的主张，实测/交付记录是另一种证据。高风险承诺要有适用条件。不能以同行做到证明本品牌也能做到。

有报告、采集和结论时先读结果与来源，检查采集范围、关键词、时间、分页、原作是否可读、评论采样及指标缺失。不要假设前一个Agent已做，也不要因为没看到本地文件就断言未采集。

## 2. 研究问题与样本设计

研究围绕四类问题开展：

- 用户：谁在什么情况下卡住？目前怎么解决？为什么不满意？什么触发他采取行动？
- 行业：需求、供给、政策、季节/节假日、技术和表达审美有什么变化？哪些是持续变化，哪些只是热点？
- 内容：同行/替代方案如何讲？哪些形式用户看得懂？哪些被反复追问、误解或反对？
- 品牌：哪些痛点能真正解决，依靠什么机制，有什么可见证据，哪些场景不适用？

建立“直接竞品、间接替代、行业知识账号、相邻赛道形式参考、自有历史”样本层。覆盖高表现、中低表现、新旧作品、不同账号规模和不同任务。高赞榜用于发现现象，不能当作整个市场的代表样本。按地区、价格带、B/C端、决策角色、使用场景、近期与历史分层。

采样规模由研究问题、差异程度、预算和结论是否趋于稳定决定，不预设每行业必须20个账号或100条作品。明确实际量和未覆盖层；新增样本不再改变主要分类时，可以结束本轮并列出仍需验证的问题。费用或接口限制时先做小批验证，不能静默全量采集。

## 3. MCP采集与研究动作

先发现当前授权品牌连接的真实工具目录和schema。研究动作与工具的历史映射见08，不能用记录中的名称推断当前会话已加载。

1. 查询品牌资料、现有增长报告、已采集作品与已完成拆解。读全相关分页及固定来源ID，记录过滤条件和覆盖。
2. 将缺口改成搜索组：品类词、用户任务词、痛点原话、场景词、替代方案词、结果/顾虑词；不要只搜品牌名或“爆款”。
3. 在当前已授权预算内补竞品/行业搜索与作品详情、评论；工具有写入式采集副作用时先识别保存位置、去重键及费用。超出范围再询问，不以研究为名采集无关个人信息。
4. 作品级拆解：标题、封面、前段、推进、证据、结果、品牌角色、CTA、形式、声音与剪辑。观察和假设分开。无法播放的视频只分析可见文字/图像，不宣称看过或听过。
5. 保存原始结果引用与提取结论。采集成功、详情解析、媒体下载、可视听、可复用和可商用分别记录。

MCP缺失时先准确记录发现结果，使用用户已给导出和本地案例继续研究；官方网页补行业信息，授权浏览器可作为适当后备。不写“系统没有该能力”，不猜接口、不取用其他项目的Token。此时不能把历史样本写成当日实采。

## 4. 评论到痛点的编码

保存最小必要评论片段、作品来源、抓取时间及上下文，不把姓名/联系方式写进通用技能库。区分：

| 评论类别 | 提供什么线索 | 常见误判 |
|---|---|---|
| 情境/失败经历 | 用户实际任务、卡点、损失 | 一个极端经历代表全行业 |
| 提问/比较 | 认知缺口、选型条件、替代方案 | 所有“多少钱”都是有效买家 |
| 异议/风险 | 不信任点、产品限制、服务顾虑 | 把反讽或竞品留言当事实 |
| 行动意向 | 问渠道、地区、购买、试用 | 留言意向直接算订单 |
| 使用/售后 | 维护难点、交付落差、复购需求 | 只挑好评忽略失败条件 |
| 情绪/娱乐/梗 | 共鸣和传播原因 | 热闹评论证明产品需求 |

检查热门排序、最新评论、作者回复与楼中楼差异；记录是否只取到高赞评论。去掉重复转述、广告、疑似异常样本，保留排除原因。评论占比的分母是本次可见样本，不是全部消费者。痛点频次、强度、行动信号和交叉证据分别呈现，不把“说得最惨”排成唯一优先级。

用至少能支撑结论的不同证据交叉核查：作品/评论与品牌销售访谈、服务记录、官方说明或用户访谈。证据数量不设伪科学门槛；只有一个来源就降低置信，不能补造第二条。

## 5. 痛点—差异化解决方案—场景卡

每张卡回答：

1. 哪个用户/决策角色，在什么触发时刻，要完成什么任务？
2. 可观察障碍是什么？货币、时间、体力、心力、风险和机会成本分别怎样表现？
3. 他当前的替代办法是什么，为什么仍有不满或权衡？
4. 品牌的产品/服务用什么机制改善哪一步？差异是相对哪个替代基线、对哪类客户有意义？
5. 哪些资料、实测、案例或交付记录支持？限制、例外、有效期与缺口是什么？
6. 能怎样拍/说/画，让用户亲眼理解？看完下一步是什么，谁承接？

“高品质、很专业、很省心”不是完整方案。把“省心”展开成用户不必分别协调哪几件事、品牌实际衔接哪几步、出现变化时如何处理。品牌与竞品都能做到的能力可作为基础资格，不强称独有；真正差异尚无证据时先以用户问题教育和验证计划开展内容。

优先级以痛点强度与频率、解决意愿、商业匹配、品牌可兑现程度、可证明性及资源成本共同判断。可用低/中/高并解释，不用未经验证的加权得分冒充事实。

## 6. 行业内容地图与趋势核查

输出：决策链/角色 → 用户问题 → 行业常见答案 → 尚未解释清楚的缺口 → 适合的形式与选题 → 品牌可进入的位置。趋势要注明发布和事件日期、地域、对象和来源，重要政策/产品能力以现行官方资料核对。课程里的旧算法、价格、固定阈值只作历史观点。

先判断“为何近期受关注”再判断“是否适合本品牌”：旅游的情绪与愿望、日用品的可见操作、工业设备的适配和采购风险不可互换。跨行业可以借表达机制，不能借用产品效果证据。研究结论进入策略卡，不能停在一份没人继续引用的报告里。

## 7. 证据台账最小字段

`source_id / 品牌范围 / 来源类型 / 原始引用 / 内容或评论定位 / published_at / collected_at / 指标窗口 / 分页与样本范围 / 可见性 / 权利状态 / 原始事实 / 推论 / 反例 / 置信与缺口 / 使用在哪张价值卡`。

来源类型至少区分：品牌真源、原始媒体观察、平台计数、自有业务事件、用户创作偏好、专家判断、第三方主张。具体身份、时间、指标未知填null并说明原因。
