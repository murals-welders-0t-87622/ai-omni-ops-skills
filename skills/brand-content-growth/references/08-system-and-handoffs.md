# 08 放进全域运营系统：职责、对象、工具与交接

## 1. 业务职责

| 角色 | 负责 | 与内容业务交接 |
|---|---|---|
| 全域增长统筹 | 共同经营目标、用户优先级、资源与跨部门取舍 | 给报告、品牌事实、瓶颈和边界；接收差量洞察与经营反馈 |
| 内容统筹/策略 | 独立研究、内容战略、组合与专业路由 | 不越权改产品/价格/全域战略；把发现提交上游 |
| 选题与创作 | 把价值卡变成选题、文案、故事和声画结构 | 提交完整正文与证据，避免只交标题与摘要 |
| 专业制作 | 决定工艺，调用实际生产能力、剪辑和视听验收 | 接完整简报/资产依赖，交真实文件和未通过项 |
| 发布与承接 | 账号、发布、链接、客服/销售、商机和交付 | 许可与承接条件清楚，回传真实业务事件 |
| 数据复盘 | 可比数据、诊断、实验、经验与反证 | 分清相关性、归因与因果；将结果送回对应层级 |
| 中台与能力网关 | 身份、品牌范围、权威对象、权限、文件、工具和回执 | 不伪装专业创作，不把工具200当业务验收 |

这是一组职责，可以由一个Codex完成，也可以映射到宿主实际注册专家。默认不因此启用多Agent。只有宿主和用户允许协作时才真实委派，保留实际执行身份；缺成员时明确由当前Agent执行，不模拟专家回话。

## 2. 对既有抖音全流程包的升级建议

现有包已覆盖策略、选题、创作、多形式生产、任务和版本记录、复盘；本轮不覆盖旧包。改造方向是先调业务路由与共享交接，再按需改专业技能：

1. 将“制定五类形式配比”前置条件改为“引用全域报告并独立核查痛点—方案—场景”，输出内容战略与任务组合，再做形式和产能安排。
2. 选题不首先按数字人/短剧/广告分槽；先按用户问题与内容任务，随后选择最合适表达形式，允许混剪、AI+真实演示等组合。
3. 六类内容任务、策略机制、叙事结构、呈现形式、制作技术分别登记；沿用专业专家，避免再建一套万能专家。
4. 文案到制作必须交完整稿件、证据与动作要求；制作配置只承接真实事实，不能重新创造承诺。
5. 复盘从“最近一周作品”扩到适合业务周期的数据，关联有效咨询、商机、交付与使用反馈；没有数据就明示边界。
6. 公共契约与长编排信息集中维护，不复制到每一个专业Skill导致方法被系统说明淹没。专业Skill负责具体工艺。

候选迁移映射：现策略专家→02/03/04；选题专家→05；文案/简报专家→05及对应行业规则；数字人/剧情/品牌广告/解释/创意/Flova等制作专家→06与各自真实技能；数据复盘专家→07；任务/版本治理→08/11。真实注册列表和工具依赖以当前包与运行端为准，本文不宣布成员安装或加载成功。

## 3. 推荐业务对象与关系

这是**设计建议/本地交换格式**，不声称数据库已有这些表或API字段。优先映射已有品牌报告、业务资产、选题、营销日历、创作包、素材、任务、作品和复盘，不为每个方法建新表。

- 品牌/产品服务事实、有效增长报告与内容战略版本。
- 痛点—方案—场景卡、研究证据及行业内容地图。
- 策略卡/系列、选题项、创作包、制作包、产物修订。
- 素材/片段、资产版本、来源与可用/权利状态。
- 发布记录、指标快照、线索/商机/订单映射、实验和经验候选。

关键关系：内容战略引用增长报告；策略引用价值卡；选题引用策略与价值；脚本消费确切证据；镜头/成片引用资产与脚本修订；发布引用成片修订；指标引用平台作品和窗口；线索/订单用可证映射关联；复盘影响新的策略/实验修订。既有业务task_id稳定，供应商job不是业务任务。

## 4. Ontology五元素的最小落法

| 元素 | 内容业务中的作用 | 实施边界 |
|---|---|---|
| Object | 品牌、产品、任务、价值卡/策略等有归属的对象 | 复用既有对象及版本化JSON，镜头不必全部建中台节点 |
| Link | 事实→策略→选题→脚本→成片→发布→反馈的关联 | 保存实际来源与修订，不能靠标题猜关系 |
| Function | 读取事实、检查缺口、计算可比指标、分析变更影响 | 模型专业判断需记录证据与不确定性 |
| Action | 保存修订、提交审阅、归档、发起授权范围内采集/生成/发布 | 服务端检查身份、品牌、前置、幂等和授权 |
| Interface | 有来源、有版本、可审阅、可恢复等共同约定 | 不把Interface等同于MCP名称或HTTP URL |

本地增强版可与Ontology和专家绑定协作；SaaS按最新双版本方向不强制引入Ontology管理和专家绑定。共同业务契约可保持一致，宿主执行映射可替换。

## 5. 当前工程中的工具定位线索

2026-10-25仅只读检查Lab本地源码。以下是**源码名称快照**，本轮没有连接品牌MCP实调，也未验证当前客户端可见性。实际执行必须发现当前schema，读取所需参数、范围和返回值。不要把名称写成无条件可调用函数。

| 业务动作 | 本地源码中可定位的名称 | 特别注意 |
|---|---|---|
| 品牌事实与产品 | `get_brand_archive_summary`、`get_brand_archive_survey`、`get_brand_products` | 读取实际品牌范围、版本、适用条件 |
| 竞品与行业线索 | `get_brand_competitor_accounts`、`get_brand_industry_feeds`、`get_brand_business_assets` | 来源与采集时间可过期 |
| 已采集内容与分析 | `list_collected_works_for_analysis`、`get_collected_work_analysis_context`、`list_work_analysis_results`、`get_work_analysis_result` | 候选不等于素材库；稳定sourceId不由URL猜造 |
| 抖音采集摘要 | `get_douyin_collection_workspace` | 描述主要是达人搜索等摘要，不等于返回所有作品/评论 |
| 补搜索/同行作品 | `sync_douyin_search_works`、`sync_douyin_competitor_works`、`sync_douyin_benchmark_works` | 有采集/保存副作用，确认预算、去重与范围 |
| 补评论 | `sync_douyin_comment_data` | 源码支持链接列表或带cursor分页；实际用当前schema |
| 深度拆解 | `get_work_analysis_taxonomy`、`create_work_analysis_request`、`submit_work_analysis_result` | 用户授权范围内可选作品，但登记委托不等于已执行专家分析 |
| 选题与营销日历 | `get_brand_growth_topic_library_workspace`、`create_brand_growth_topic_library_item`、`get_brand_growth_marketing_calendar_workspace`、`update_brand_growth_marketing_calendar` | 读回对象和版本，独立内容子项不与备选标题混算 |
| 方案与归档 | `get_ai_control_center_marketing_plans`、`create_ai_control_center_marketing_plan`、`manage_growth_reports` | 先核对象类型、正文和附件能力，不把内容策划误写成全域报告 |
| 新增事实候选 | `manage_brand_library` | 内容推论不能自动覆盖已确认品牌事实 |

现有拆解平台枚举为`douyin/xiaohongshu/wechat`，相关权限与错误描述将`douyin`用于“抖音/视频号”业务区、`wechat`对应公众号采集。**业务区合并不证明已有独立视频号采集或后台留存权限。** 操作视频号时确认真实数据源/账号/指标，不能把公众号数据当视频号，也不能用抖音样本冒充视频号独立研究。

源码定位：`apps/server/src/modules/openclaw/openclaw.service.ts`、`work-analysis.tools.ts`、`work-analysis.contract.ts`。具体路径与hash在研究核验记录，不打包连接密钥。

## 6. 可恢复的交接信封

每次交接保存：品牌范围、权威task引用（若有）、工作范围/终点、输入产物ID/修订/文件hash、完整正文或可读文件、证据引用、缺口、授权摘要与待确认项、下一责任人/动作、产物及实际使用技能版本。供应商job另列真实ID和状态。

只有从服务端读到的正式ID才写作正式任务/阶段/修订。离线草稿使用本地文件标识并注明未归档，不推测generation或状态枚举。文件批准要绑定确切修订；改后新增文件，不原地修改已登记产物。

写后独立回读正确品牌、ID、修订、完整正文、文件可访问与UI必要展示。权限拒绝或回执不明保留状态，先查询，不换Token扩权、不重复建任务。归档成功不触发发布。

## 7. 系统优化建议与验收

| 优先 | 具体能力 | 解决的问题 | 业务验收 |
|---|---|---|---|
| P0 | 价值卡与来源可回溯，内容明确引用有效报告/产品 | 内容偏离用户和品牌、承诺无据 | 从一条成片能追到场景/方案/来源，事实变更能定位受影响内容 |
| P0 | 已采集作品/评论/拆解的覆盖和时间可查 | 重复采集、盲信旧结论 | 新Agent能解释已有和缺口，只补缺的采集 |
| P0 | 营销日历子项、素材就绪度、内容/实验身份 | 假批量、日期误判、素材不足仍出片 | “做今天内容”能列真实条目，缺素材能自动补或明确卡点 |
| P0 | 成片—发布—线索—商机的实际映射和指标字典 | 高互动冒充增长 | 复盘区分互动与有效结果，未知/0/延迟回补正确 |
| P1 | 素材片段、真实型号、权利和跨片复用记录 | 声画不符、混SKU、七条像一条 | 按主张找到对应动作，整批复用可复核 |
| P1 | 当前能力schema、预算、回执和恢复整合 | 选错模型、超时重收费 | 断点恢复不重提已在途job；制作链能从文件继续 |
| P1 | 销售客服与服务反馈→价值卡/选题候选 | 内容做完不再学习 | 一条真实异议可回传并进入新的有证据选题 |
| P2 | 公域/GEO/销售/使用内容的派生与版本推荐 | 同一事实多处不同说法 | 统一事实，派生内容保留来源与当前适用版本 |

以上均是候选改进，不表示已在应用实施；需按Lab工程规范、现有能力复用、用户范围及自然语言用例分期。不要为做内容技能重构整个中台或触碰原系统。
