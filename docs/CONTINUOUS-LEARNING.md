# 技能持续学习机制

用户反馈、实际运行缺口、WorkBuddy专业方法、GitHub原项目，以及用户提供的文章/文件，共同驱动本库持续优化。目标是更贴合真实经营、更丰富和稳定；不通过增加概念或堆原文证明“学会”。

**现有业务框架保持：** 总统筹→领域与工艺→专业知识；生意模式→战略→策略→执行→数据反馈。增加本领域方法和可靠性不需要反复询问；确需改变主结构、总职责或交接语义时，先提交具体差异与影响，等用户确认。

## 每次怎么做

1. 定位这次要完成的业务和真实缺口，先查本库是否已有能力。
2. 按任务搜索已授权WorkBuddy技能/专家、GitHub官方/原作者、用户材料及相关官方技术文档。
3. 记录实际读取范围、版本/hash、适用条件、依赖、许可与原作者主张；关键方法看源码/原文，不只看README或名字。
4. 分类写回既有领域：运营方法、策略机制、制作工艺、工具适配、测量或可靠性。品牌专属资料/经营经验进品牌中台。
5. 做与改动相称的验证：脚本实际运行；视频工艺检查时间、资源、短段/随机seek和解码；经营方法用普通业务委托和真实回执验证。未做的明确留待验。
6. 更新方法版本、来源采用记录、CHANGELOG和发布清单，通过后同步专用Git。业务系统发布与客户触达不随此流程自动执行。
